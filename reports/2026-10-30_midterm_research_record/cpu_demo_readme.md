# CPU 서비스 분류 시연

공개 CESNET 평가 PPI를 재생하여 실제 학습된 모델이 이 Mac의 CPU에서 추론하는 로컬 시연이다. 외부 전송·패킷 캡처·새 학습은 하지 않는다. 첫 최대30패킷의 간격·방향·크기를 사용한다.

## 실행

프로젝트 폴더에서 다음 명령을 실행하고 브라우저에서 `http://127.0.0.1:8768`을 연다.

```sh
sh experiments/2026-10-30_midterm_restart/run.sh cpu_demo.py --models M5 --port 8768
```

이 명령은 **학생 M5만 메모리에 로드**한다. 교사 없이 학생이 추론한다는 점을 확인할 수 있다. M0~M5를 모두 비교하려면 `--models M5`를 생략한다. 종료는 실행한 터미널에서 Ctrl+C다. 서버는127.0.0.1에만 바인딩한다.

## 발표 시 조작

1. 평가월과 표본번호0~59를 선택한다. 서비스당3개를 고정 난수로 뽑았으며 모델 예측을 보고 잘 맞힌 샘플만 고르지 않았다.
2. `CPU에서 분류`를 누르면 top3 확률을 계산한다. 실제 정답 표시는 기본적으로 꺼져 있다.
3. `실제 정답 표시`로 맞혔는지 확인한다. 틀린 예측도 그대로 보여준다.
4. `다음 표본`으로 이동한다. 짧은 플로우도 포함되며 유효 패킷 수를 보여준다.
5. 필요하면 원본ID와3×30 PPI를 펼쳐 본다. 정답과 교사 확률을 입력 채널로 붙이지 않았다.

대표 Google 포함20·클래스당200개·본seed201의 검증된 checkpoint를 사용한다. 최종 평가점수로 가장 좋은 seed를 고른 것이 아니다. 시연의6개 고정 플로우×6모델=36개 CPU 예측라벨을 보존된 월별 평가 예측과 대조했다. 현재 검증 상태와 정확한 코드 해시는 [검증 JSON — 원본 로컬 보관](../../PUBLICATION.md#omitted-artifacts)에 있다.

브라우저에서는 M5 단독 실행, 정답 표시, 다음 표본, 범위 밖 표본번호 거부, 4월→5월 전환을 확인했다. [UI 확인 기록 — 원본 로컬 보관](../../PUBLICATION.md#omitted-artifacts)에는 틀린 예측이 그대로 표시된 사례도 기록했다.

## 설명할 때 구분할 것

- 실제 CPU 추론이지만 **실시간 네트워크 패킷 수집은 아니다.** 이미 전처리된 공개 PPI를 재생한다.
- 표시된1회 연산시간은 초기 실행·캐시·시스템 부하 영향을 받는다. 정식warm-up·1,000회 반복 CPU 벤치마크와 혼동하지 않는다.
- M0의16통계 계산과 신경망 내부변환은 해당 연산시간에 포함되지만 패킷수집 대기·입력파일 로딩·네트워크 요청시간까지의전체지연은 아니다.
- softmax확률은 별도로 보정된 정답 확률이 아니다. 등록20서비스 중 하나를 고르는 폐쇄형 분류이며 미등록 서비스 탐지나 이상 탐지를 구현한 것으로 말하지 않는다.
- 다른 서비스 구성·라벨 수의 결과는 연구 원장의 전체 평가표로 설명한다. 이60개 시연 표본을 성능 검증셋으로 사용하지 않는다.
