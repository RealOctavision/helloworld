# 중간평가 재실험: M0~M5 모델 구조 검토

기록일: 2026-10-28. 이 문서는 합의한 실험 범위와 이번에 사용할 구조의 권고안을 구분한다. 기존 구현을 재실험 명세와 직접 대조한 자체 검토이며, 독립 검증이나 학습 완료 보고가 아니다.

**2026-10-30 선택 확정 보충:** 사용자가 설명 원문을 제공했고 기존 선택과 대조했다. 교사는 pooling 직후448→분류기(20클래스695,593개), M2는 전체 미세조정, M1 BN 통계 갱신/M2 사전학습 BN 통계 유지, GeM의 기본 학습 가능한 p 유지로 정했다. 학생은 기본3층 CNN(20클래스20,180개) 하나로 진행하며 residual/dilated 후보 비교는 여유 시 또는 중간발표 이후다. KD 후보는 α={0.1,0.25,0.5}, T={1,2,4}, 공통 α·T, 개발용2회다. 아래의 '권고·미정'과 상태표는 10월28일 검토 이력이며 **최신 선택은 [결정 기록 §8 — 원본 로컬 보관](../../../PUBLICATION.md#omitted-artifacts)**을 따른다. 구조 선택 확정은 새 학습 코드 구현·성능 검증 완료를 뜻하지 않는다.

새 정제 데이터셋과 학습 실행은 아직 없다. 데이터·평가 원칙은 `restart_decisions.md`가 기준이다.

## 2. 공통 입력과 여섯 모델의 역할

입력은 처음 **최대 30패킷**의 IPT·DIR·SIZE다. 설명할 때 SIZE·DIR·IPT 순으로 나열해도 실제 배열의 채널 순서는 **[IPT, DIR, SIZE]**, 형태는 `[batch, 3, 30]`으로 고정한다. IPT 단위는 ms, SIZE는 데이터가 정의하는 패킷 크기 bytes다. 짧은 플로우는 남는 위치를 0으로 패딩한다. DIR가 0인 위치가 패딩이며, 실제 IPT가 0인 패킷은 유효하다.

공식 교사 변환은 유효 SIZE를 1~1,500, IPT를 0~65,000으로 제한하고 패딩을 다시 0으로 돌린다. 이번 입력에는 첫 1초 같은 별도 시간 절단을 적용하지 않는다. SNI·IP·서비스 라벨·FLOWSTATS는 신경망 입력이 아니다.

| 모델 | 구조 | 시작점과 학습 신호 | 추론 입력 |
|---|---|---|---|
| M0 | PPI 파생 통계 → LightGBM | 실제 정답 | 동일한 PPI에서 계산한 통계 |
| M1 | 30pktTCNET backbone → C클래스 선형층 | 공개 학습 가중치 없이 직접학습, CE | PPI |
| M2 | M1과 같은 구조 | 공개 backbone 가중치 + 새 분류층, CE 미세조정 | PPI |
| M3 | 작은 3층 CNN → masked mean → 분류층 | 실제 정답, CE | PPI |
| M4 | M3와 같은 구조 | 실제 정답 + M1 확률, CE + KL | PPI; 교사 불필요 |
| M5 | M3와 같은 구조 | 실제 정답 + M2 확률, CE + KL | PPI; 교사 불필요 |

여기서 C는 서비스 수다. M0는 트리 모델 1종, M1/M2는 큰 신경망 구조 1종, M3/M4/M5는 작은 신경망 구조 1종이다. 여섯 개의 서로 다른 신경망 구조를 만드는 비교가 아니다.

## 3. M0: 같은 관측 구간의 통계 + LightGBM

기존 A100 코드에서 그대로 검토할 수 있는 시작 후보는 **16개 통계**다.

| 묶음 | 특징 | 수 |
|---|---|---:|
| 길이·방향 | 유효 패킷 수, 정방향 수, 역방향 수, 연속 패킷 간 방향 전환 수 | 4 |
| IPT | 평균, 표준편차, 최솟값, 최댓값, 합계, 중앙값 | 6 |
| SIZE | 평균, 표준편차, 최솟값, 최댓값, 합계, 중앙값 | 6 |

모두 첫 최대 30패킷의 유효 위치에서만 계산한다. IPT 합은 이 관측 구간의 간격 합이며 전체 플로우 DURATION과 다르다. 기존 함수의 표준편차는 `np.nanstd` 기본값인 ddof=0이다. 첫 패킷의 IPT=0은 포함되므로 IPT 최솟값은 정보가 적을 수 있다. 이를 포함한 특징 목록은 검증 단계에서 결정한 뒤 고정하고, 평가 결과를 보고 바꾸지 않는다.

트리는 특징값의 분기 조건을 여러 단계 결합하며 여러 트리를 누적해 서비스별 점수를 만든다. 패킷별 순서를 원형 그대로 처리하는 CNN과 표현이 다르므로, M0가 잘 나오면 이러한 요약 통계만으로도 충분한 조건이 있다는 뜻이다. 전체 FLOWSTATS를 먼저 줘서 이득을 얻는 기준선으로 만들면 이번 비교의 입력 조건이 달라진다.

기존 설정은 최대 500 boosting rounds, 학습률 0.05, num_leaves=15, min_child_samples=20, reg_lambda=1, 검증 조기종료 30이었다. 이는 **기존 구현값**이며 이번 최종 설정으로 승인·검증된 값은 아니다. 출력 클래스 수, 선택된 트리 수, 모델 파일 크기, CPU 비용을 기록한다. 신경망 파라미터 수와 같은 의미의 고정 파라미터 숫자를 임의로 붙이지 않는다.

## 4. M1·M2: 원 논문의 전이 경로와 공개 backbone의 구분

**동일성 설명 보완:** 처음 권고한 `backbone_model + Linear(448,C)`는 공식 backbone의 feature refinement까지 포함한다. [원 논문 §V-A](https://arxiv.org/html/2502.12930v2#S5.SS1)는 전이실험에 global pooling 이후·feature refinement 이전의 특징을 사용한다고 명시한다. 같은 공개 모델 계열이라는 것과 논문의 전이 분류 경로가 동일하다는 것은 구분해야 한다.

논문의 전이 경로에 맞춘 수정 권고는 **stem → residual CNN → pooling → 새 Linear(448,C)**다. refinement와 256차원 compression neck을 모두 제외한다. 보존한 공식 tc-transfer 코드도 `CNN_BACKBONE_PLUS_GEM_POOLING`에서 이 경로를 지원한다. 아직 새 학습 파이프라인을 구현·실행한 것은 아니며 실행 manifest에서 최종 경로를 고정해야 한다. 아래 그림은 이 수정 권고다.

```text
PPI [B,3,30]
  → 패킷 임베딩 [B,32,30]
  → residual bottleneck 4개 [B,448,30]
  → GeM pooling [B,448]
  → 새 Linear(448,C) [B,C] logits
```

패킷 임베딩은 SIZE 20차원, IPT 10차원, DIR의 정·역방향 표시 2차원을 합쳐 32차원이다. SIZE 표는 1,501×20=30,020개, IPT 구간 임베딩은 200×10=2,000개 학습 파라미터다. 방향 표시는 학습 파라미터가 없다. 같은 원본 특징을 모델 내부에서 벡터로 바꾸는 과정이며 추가 외부 특징을 입력하는 것은 아니다.

각 residual block은 좁은 채널에서 패턴을 계산하고 넓은 채널로 복원한 뒤 shortcut을 더한다. 실제 모듈은 다음과 같으며 stride는 모두 1이고 패킷 축 길이 30을 유지한다.

| 블록 | 1×1 → 시간축 합성곱 → 1×1 | 시간축 커널 | 파라미터 수 | dropout |
|---|---|---:|---:|---:|
| 1 | 32→48→48→192 | 7 | 33,984 | 0 |
| 2 | 192→64→64→256 | 7 | 107,776 | 0.1 |
| 3 | 256→96→96→384 | 5 | 207,744 | 0.2 |
| 4 | 384→112→112→448 | 3 | 305,088 | 0.3 |

블록에는 BatchNorm, ReLU, shortcut 변환이 포함된다. GeM은 패킷 위치들을 요약하는 pooling으로 지수 p가 3에서 시작하고 공식 모델에서 학습 가능한 파라미터 1개다. 기존 일부 후속 코드의 p 고정·안정화 구현이나 BatchNorm 고정을 기본 경로에 조용히 섞지 않는다. 수치 안정성 처리가 필요하면 적용 범위와 양쪽 교사의 동일 적용 여부를 기록한다.

처음의 refinement 포함 경로는 backbone 888,661 + 분류층 449×C로 20클래스 **897,641개**였다. refinement의 202,048개를 제외한 수정 권고는 686,613 + 449×C, 즉 **20클래스 695,593개**다. 새 CPU 구조 probe로 이 수와 출력 형태를 확인했다. 공개 wrapper 전체는 1,004,117개이며 별도 Linear(256,20)을 붙이면 1,009,257개다. 이 세 경로의 숫자를 혼용하지 않는다. 이전 strict checkpoint 로드 결과는 보존했고, 추가 probe는 가중치 다운로드나 학습 없이 구조만 확인했다.

M1은 공개 학습 가중치를 불러오지 않고 목표 데이터로 학습한다. 주의할 점은 공식 무가중치 생성자의 SIZE/IPT 임베딩이 **데이터 비의존 PLE 초기화**라는 것이다. 서로 다른 seed에서 임베딩 초기값은 같고 CNN 초기값은 달랐다. 따라서 '공개 사전학습 가중치 없이 학습'이 정확한 설명이다. 모든 텐서를 난수로 초기화하는 별도 조건을 추가할 필요는 없다.

M2는 2022년 공개 사전학습 backbone과 새 C클래스 분류층을 목표 데이터에 미세조정한다. 기본 권고는 backbone도 업데이트하는 미세조정이며 head만 학습하는 frozen linear 조건과 구분한다. M1/M2의 구조와 목표 표본·기본 학습 일정은 맞추고, 검증에 사용하는 튜닝 범위도 명시한다.

원 논문의 전이실험은 BN의 통계 고정, 학습 일정, 과제별 pooling/학습률 탐색, L2SP·LDIFS 등의 설정을 사용했다. 이번 데이터·라벨 예산·시점 분할과 학습 설정은 별도로 정하므로, 구조를 맞추더라도 원 논문 실험 전체를 그대로 재현했다고 표현하지 않는다. 미세조정된 M2를 원천 데이터에서 사전학습하는 실험으로도 부르지 않는다. 원 논문은 작은 학생이나 M4/M5 증류 구조를 제공하는 근거가 아니며, 해당 부분은 우리 비교 설계다.

공식 교사는 CNN의 매 층과 GeM에서 학생처럼 명시적인 유효 길이 마스크를 적용하지 않는다. 입력 패딩은 0이지만 후속 연산이 자동으로 패딩을 무시한다고 설명하면 안 된다. 공식 동작을 유지하는 것과 마스크를 새로 추가한 모델은 별도 설계다. 짧은 플로우 성능도 함께 해석한다.

## 5. M3·M4·M5: 계획서의 작은 CNN

```text
PPI [B,3,30] + 원래 DIR에서 계산한 유효 위치 마스크
  → 고정 전처리
  → Conv1D(3,32,k=3,padding=1) → ReLU → 마스크
  → Conv1D(32,64,k=3,padding=1) → ReLU → 마스크
  → Conv1D(64,64,k=3,padding=1) → ReLU → 마스크
  → 유효 위치의 평균 [B,64]
  → Linear(64,C) [B,C] logits
```

stride·dilation은 1, 합성곱과 선형층의 bias는 사용한다. 이 계획서 구조에는 BatchNorm·dropout·별도 학습 임베딩·추가 projection이 없다. 마스크는 특징 제거 전에 원래 DIR에서 계산하고 각 CNN 블록 뒤 다시 적용한다. 방향 채널 제거 실험에서도 마스크까지 지워 모든 패킷을 패딩으로 만들지 않는다.

전처리 시작 후보는 `log1p(IPT)/log1p(65000)`, DIR 유지, `SIZE/1500`이다. 추가 데이터의 통계를 요구하지 않는 고정 변환이며, 이번 구조 probe에서도 사용했다. 아직 이번 검증셋에서 성능을 확인해 선택한 최종 변환은 아니다. 어떤 변환을 선택하든 M3/M4/M5에 동일하게 적용한다.

| 계층 | 파라미터 계산 | 20클래스 기준 |
|---|---|---:|
| Conv1 | 3×32×3 + 32 | 320 |
| Conv2 | 32×64×3 + 64 | 6,208 |
| Conv3 | 64×64×3 + 64 | 12,352 |
| 분류층 | 64×20 + 20 | 1,300 |
| 합계 | 18,880 + 65×C | **20,180** |

실제 CPU 구조 확인용 인스턴스를 생성해 위 수와 출력 형태를 확인했다. refinement 포함 교사 대비 약 1/44.5, 논문 전이 경로에 맞춘 수정 권고 교사 대비 약 1/34.5 크기다. 이 비율을 CPU 속도 향상 배수로 해석하지 않는다.

이 학생은 각 위치에서 최대 7개 인접 패킷 범위의 패턴을 계산한 뒤 전체 유효 위치를 평균낸다. 전체 30패킷은 사용하지만 넓은 구간의 순서 관계를 직접 표현하는 능력은 제한될 수 있다. 이는 검증할 구조의 특성이며 아직 관측한 성능 결과가 아니다.

### 5.1 학생 구조 대안과 선택 원칙

현재 3층 CNN은 단순하고 설명 가능한 기준안이며 **최선으로 검증된 구조가 아니다.** 대안을 비교하는 목적은 우리 데이터의 성능·CPU 비용에 맞는 학생을 찾는 것이며 문헌의 다른 데이터 성능을 그대로 기대하지 않는다.

| 후보 | 변경·목적 | 이번 판단 |
|---|---|---|
| 현재 3층 CNN | 근처 패킷 패턴을 계산하고 유효 위치 평균 | 유지할 기준선 |
| 작은 residual/dilated CNN | 잔차 연결과 팽창 합성곱으로 더 넓은 패킷 구간의 관계를 처리 | 가장 먼저 비교할 대안 |
| Depthwise separable 1D CNN | 시간축 합성곱과 채널 결합을 분리 | 계산량 절약 후보; 실제 CPU 지연은 측정 필요 |
| 작은 GRU | 순서대로 상태를 갱신해 흐름을 요약 | 순서 표현 대안; CPU에서의 순차 처리 비용 확인 필요 |

구체적인 residual/dilated 후보의 설계 예시는 3→32, 커널3 stem 뒤에 채널32의 두 합성곱 잔차 블록 3개(dilation 1·2·4)를 놓고 masked mean과 Linear(32,C)를 쓰는 것이다. 각 합성곱에 bias를 사용하고 별도 정규화 학습 파라미터가 없다는 가정에서 20클래스 **19,604개라는 설계 계산값**이 나온다. 시간축 receptive field는 31 위치다. 실제 구현·학습 결과가 아니며 최종 채널·정규화·패딩을 바꾸면 수치도 달라진다. 30패킷 전체를 관측한 뒤 분류하므로 양방향 문맥을 사용하는 팽창 CNN으로 만들 수 있으나, 원 TCN의 causal 구조를 그대로 복제했다고 부르지는 않는다.

이 후보의 근거는 [TCN 논문](https://arxiv.org/abs/1803.01271)의 잔차·팽창 합성곱 설계다. Depthwise 분리 아이디어는 [MobileNets](https://arxiv.org/abs/1704.04861)에서 차용할 수 있지만 원 논문은 이미지 모델이며 QUIC에서의 이득을 증명한 근거가 아니다.

권고 절차는 200개 조건에서 현재 CNN과 작은 residual/dilated 후보부터 직접학습 M3로 제한적으로 비교하고, 공통 2월 검증의 Macro-F1·반복 변동·CPU 지연·모델 크기로 선택하는 것이다. 입력·정제·표본·검증·튜닝 예산을 맞추고 가능한 한 약 2만 파라미터대로 비교한다. 선택한 구조는 M3/M4/M5에 모두 동일하게 사용한다. 직접학습에서 선택한 구조가 KD에서도 최적이라는 보장은 없으므로 결론은 선택한 구조 범위로 한정한다. 4·5월 평가나 겹침/비겹침 테스트 점수로 구조를 고르지 않는다. 후보 실험은 아직 실행하지 않았고 본 비교 120회에 자동으로 곱하지 않는다.

## 6. M4·M5의 차이는 교사이며, 학생 입력은 그대로다

M3의 손실은 실제 정답과의 CE다. M4/M5는 같은 표본에 대해 다음 손실을 사용한다.

```text
L = (1 − α) CE(student_logits, 실제 정답)
    + α T² KL(softmax(teacher_logits/T) || softmax(student_logits/T))
```

교사 예측 확률과 실제 정답은 **학습 손실을 계산하는 정보**다. 학생의 입력 벡터 뒤에 라벨이나 확률을 붙이는 방식이 아니다. 추론할 때는 학생 하나와 PPI만 필요하다. 이번 기본 비교에 교사 hard label로 정답을 대체하는 조건이나 추가 무라벨 데이터 확장을 섞지 않는다.

- M4의 교사는 같은 서비스 구성·라벨 수·반복의 M1 checkpoint다.
- M5의 교사는 같은 서비스 구성·라벨 수·반복의 M2 checkpoint다.
- 50개 학생에 1,000개 라벨로 학습한 교사를 붙이면 목표 라벨 예산이 달라진다. 이번 비교에서는 그렇게 하지 않는다.
- 증류 시 교사는 eval 모드와 gradient 비활성 상태로 고정하고, 학생만 업데이트한다. BatchNorm 상태도 바뀌지 않게 한다.
- 같은 반복의 M3~M5는 초기 가중치를 복제하고 학습 순서·기본 학습 일정을 맞춘다. 최적 checkpoint는 공통 2월 검증으로 선택한다.
- α·T의 값과 검증 탐색 범위는 아직 최종 고정하지 않았다. 기존 α=0.5,T=2를 자동 확정하지 않는다. α=0 비교는 수학적으로 직접학습 기준선과 연결되며 결과를 보고 테스트에서 조절하지 않는다.
- 원본 모델의 logits를 CE에 넣고, softmax는 예측 확률 표시나 KD 계산에 사용한다.

### 8.1 겹치는 평가 입력과 겹치지 않는 평가 입력의 결과

사용자 요청에 따라 **전체 / 실제 학습 PPI와 정확히 겹침 / 실제 학습 PPI와 비겹침**의 성능·표본 수·비율·클래스 support를 별도로 보고한다. 동일 원본 flow ID의 재사용은 허용하지 않고, 미래에 발생한 다른 flow의 입력 패턴 재등장을 분류하는 것이다. 라벨은 그룹 키에 넣지 않는다.

같은 seed·라벨 예산의 M0~M5는 동일한 평가 그룹을 사용한다. 예산·seed가 달라져 겹침 그룹이 바뀌는 점을 설명하고, 전체 학습 manifest 합집합과 검증 어디에도 없는 **공통 미관측 부분집합**도 별도로 보존한다. 세부 정의와 빈 그룹·부재 클래스 처리는 `restart_decisions.md` §4.1을 따른다. 이 분석은 같은 평가 예측을 분리해 계산하므로 추가 재학습이 필요하지 않다.
