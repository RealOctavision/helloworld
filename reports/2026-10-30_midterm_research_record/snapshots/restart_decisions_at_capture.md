# 중간발표 재실험: 모델·입력·중복 처리 결정

기록일: 2026-10-28 (Asia/Seoul)

최신 사용자 선택 기록: **2026-10-30, 아래 §8의 1~17번**. 사용자가 직접 지정한 선택은 그 기록을 우선한다. 사용자가 설정 설명 원문을 제공하여 **1~11번의 원문 누락 문제는 해소했고**, 선택지와 수치를 §8.1에 연결했다. §1~7의 '권고·미정'은 당시 상태이며 최신 선택과 충돌하면 §8을 따른다. 이후 사용자가 '진행해'라고 승인하여 **§9의 실제 데이터 준비와 짧은 CPU 학습 연결 점검까지 완료했다.** GPU 실행·개발 탐색·본 실험은 아직 수행하지 않았다.

이 문서는 채팅에서 확정한 범위와 후속 아이디어를 보존한다. 2026-10-28 사용자는 평가 재검토안에 동의하고, 중간평가 범위를 처음 최대 30패킷의 PPI로 M0~M5를 비교하는 것으로 정했다. 기본 비교 이후 FLOWSTATS 조합과 두 공개 사전학습 모델 비교로 확장한다. 아래에서 사용자 확정 범위, 원래 계획서의 조건, 실행 전 조정이 필요한 항목을 구분한다. 정제 데이터셋 생성과 새 학습은 아직 실행하지 않았다.

최신 합의: **Google 포함 20개에서 클래스당 200개를 먼저 비교하고, 50·100·1,000개로 확장한다. 이후 Google 미포함 서비스와 Google 계열만의 구성을 각각 비교한다. Google 계열도 1월 정제 후 고유 입력 1,000개 이상인 서비스만 선정한다.** 현재 감사에서 이 기준을 충족하는 Google 계열은 20개다. 이는 사용자의 최신 변경이며 직전의 'Google 계열 24개 전체 유지' 방침을 대체한다. 평가에는 전체·학습 PPI와 겹침·학습 PPI와 비겹침 결과를 각각 제시한다.

## 1. 사용자가 확정한 현재 범위

- 주 모델 계열은 `30pktTCNET_256`이다.
- 현재 신경망 입력은 처음 **최대 30패킷의 PPI(IPT·DIR·SIZE)**로 한정한다.
- FLOWSTATS, QUIC 메타데이터, SNI, 주소 정보는 현재 입력에 추가하지 않는다.
- '최대 30패킷'과 '실제 패킷이 30개 이상인 플로우만 사용'은 다른 조건이다. 후자의 길이 제한은 확정하지 않았다.
- 계획서의 M0~M5 비교를 이번 중간평가 범위로 정한다. 이전 실험 결과를 새 정제 데이터 결과로 간주하지 않는다.
- 평가 구성은 사용자 동의로 확정했다. 자연 발생한 PPI 반복을 포함하는 원본 시간차 평가가 주 결과다. 추가로 **해당 실행의 실제 학습 PPI와 겹치는 평가 표본 / 겹치지 않는 평가 표본**을 분리해 성능을 보고한다. 학습·개발 어디에도 없는 공통 부분집합 평가도 유지한다. 동일 원본 기록의 누수와 별개 플로우의 PPI 재등장은 구분한다.
- 현재 작업은 합의 기록과 모델 구조 검토다. 대규모 학습 캠페인은 아직 시작하지 않았다.

| 모델 | 역할 |
|---|---|
| M0 | 같은 처음 최대 30패킷에서 만든 통계를 사용하는 LightGBM 기준 모델 |
| M1 | 30pktTCNET 기반 분류 구조를 공개 학습 가중치 없이 직접학습. 공식 생성자의 데이터 비의존 PLE 초기화와 무작위 CNN 초기화를 구분 |
| M2 | 같은 분류 구조에 공개 사전학습 가중치를 적용하고 미세조정 |
| M3 | 작은 PPI 학생을 정답으로 직접학습 |
| M4 | M1의 예측을 이용해 M3와 같은 구조의 학생을 증류 |
| M5 | M2의 예측을 이용해 M3와 같은 구조의 학생을 증류 |

M1/M2의 분류 구조와 M3/M4/M5의 학생 구조를 각각 맞춘다. 같은 데이터 구성·seed에서 학습 flow ID, 정답 예산, 평가 집합을 공유한다. M0의 통계는 전체 플로우 통계가 아니라 같은 PPI 관측 구간의 통계다.

## 2. 기본 비교 이후의 확장: FLOWSTATS 조합과 mm_cesnet_v2

사용자가 제안한 진행 순서는 다음과 같다. 후속 단계의 구체적 조합·실행 횟수는 아직 확정하지 않았다.

1. 중간평가: PPI 전용 M0~M5의 성능과 실행 비용 비교.
2. 후속 입력 비교: 대표 모델에서 PPI, 선택한 FLOWSTATS 묶음, 둘을 결합한 입력을 비교한다. 가능한 한 같은 flow ID·라벨 예산·분할을 유지하고, 입력 추가로 달라진 구조와 파라미터 수도 보고한다. 단순히 모든 조합을 M0~M5에 곱하지 않는다.
3. 후속 공개 모델 비교: `30pktTCNET_256`과 `mm_cesnet_v2`를 목표 서비스에 맞게 적응시켜 비교한다. 입력 추가 효과를 확인하는 2단계와, 서로 다른 공개 모델 패키지를 비교하는 3단계의 결론을 구분한다.

| 후보 | 입력 및 목적 |
|---|---|
| T-MM | 공개 `mm_cesnet_v2`를 우리 클래스에 미세조정. PPI + 공식 FLOWSTATS 43개를 사용하는 추가 교사 |
| S-KD-MM | T-MM의 예측으로 PPI 전용 학생을 학습. 추론 시 학생은 FLOWSTATS를 받지 않음 |

연구 질문: 전체 플로우를 관측한 교사의 지식이 처음 최대 30패킷만 보는 경량 학생을 개선하는가?

- 두 공개 모델은 입력·구조·크기·원래 학습 목적·원천 학습 구성이 다르므로 성능 차이를 FLOWSTATS만의 효과로 단정하지 않는다.
- mm_cesnet_v2의 사전학습 효과 자체를 주장하려면 같은 구조의 무작위 초기화 비교가 추가로 필요하다.
- 공개 mm_cesnet_v2 가중치는 43차원 통계와 기존 102클래스 출력에 맞춰져 있다. 우리 클래스로 분류기를 교체하여 적응시켜야 한다.
- 40차원으로 줄이면 공개 43차원 입력층과 그대로 호환되지 않는다. 입력층 수정이나 재학습을 명시해야 한다.
- PPI 전용 추론과 전체 FLOWSTATS 추론은 관측 완료 시점이 다르다. 전체 통계의 이점을 초기 시점의 성능이라고 표현하지 않는다.
- 모든 입력 조합을 모든 M0~M5 및 두 교사 구조에 곱하는 실험은 확정하지 않았다.

## 3. 현재 중복 검사의 정확한 해석

소스: `raw_summary.csv`, `flowstats_collision_summary.csv`, `manifest.json`.

대상은 보유한 XS 파일의 2024-06~2025-05 전체 12개월을 합친 선택 서비스 기록이다. 아래 비율은 학습에 실제로 선택할 표본의 비율도, 월별 비율의 평균도 아니다. 미래 월을 포함한 전체 감사 결과로 학습 정제 대상을 선정하지 않는다.

| 서비스 구성 | 길이 처리 | 전체 행 수 | 다른 라벨과 같은 입력을 공유하는 행 수 | 비율 |
|---|---|---:|---:|---:|
| Google 미포함 20개 | 짧은 플로우 포함, 30까지 패딩 | 2,473,372 | 25,794 | 1.042868% |
| Google 포함 20개 | 짧은 플로우 포함, 30까지 패딩 | 5,172,979 | 57,745 | 1.116281% |
| Google 미포함 20개 | 실제 30패킷 이상 | 1,299,518 | 185 | 0.014236% |
| Google 포함 20개 | 실제 30패킷 이상 | 2,857,217 | 27 | 0.000945% |

다른 라벨과 같은 입력을 공유하는 그룹에 속한 모든 행을 센 값이며 오분류율을 뜻하지 않는다. 동일 입력·동일 라벨 반복도 별도로 존재한다. 원본 ID가 다른 별개의 통신이 같은 PPI를 가질 수 있으므로, PPI 일치만으로 수집 파일의 잘못된 복제라고 단정하지 않는다.

**'전체 패킷을 보면 중복이 없다'고 확인한 것은 아니다.** 현재 자료에는 첫 30패킷의 개별 PPI와 전체 구간의 요약 통계·히스토그램이 저장되어 있다. 모든 패킷의 개별 시퀀스를 검사하지 않았다.

- 실제 30패킷 이상인 두 구성에서는 PPI30 + 기본 전체 통계 5개로 동일 입력이 관찰되지 않았다.
- 짧은 플로우를 포함하면 같은 구성에서도 라벨 충돌이 남았다: 미포함 20개 543행, 포함 20개 14,690행.
- 히스토그램 32개를 더해도 위 두 충돌 행 수는 같았다.
- 이 추가 검사는 PPI 요약 3개·종료 사유 3개까지 포함한 공식 FLOWSTATS 43개 전체 검사가 아니다.

## 4. PPI 전용 재실험의 중복 처리 — 학습 정제 방향·주/보조 평가 구성 동의, 아직 미실행

목적은 관측 가능한 PPI 패턴의 반복 편중을 줄이고, 학습·평가 간 패턴 재등장 효과를 구분하는 것이다. 정확도가 반드시 향상된다는 보장은 없다.

1. 학습·개발·평가 기간과 서비스 목록을 먼저 고정한다. 평가 라벨을 이용해 학습 기록을 삭제하거나 다시 선택하지 않는다.
2. 학습에 사용하기로 허용한 데이터·정답 범위 안에서 입력을 그룹화한다. 여러 달의 정답을 모두 보고 충돌을 제거한 뒤 '소수 라벨만 사용했다'고 주장하지 않는다. 별도 정제용 라벨 접근이 있었다면 명시한다.
3. 동일한 PPI에 하나의 서비스 라벨만 있는 그룹은 학습용 대표 1개를 남긴다. 원본 ID와 그룹 빈도는 별도로 보존한다. 대표 선택은 고정 seed 등 재현 가능한 방법을 쓴다.
4. 학습 범위에서 동일한 PPI에 여러 서비스 라벨이 있는 그룹은 전부 별도 격리하여 이번 명확한 입력·정답 대응을 보는 학습에서 제외한다. 다수 라벨을 정답으로 바꾸거나 임의의 한 서비스만 남기지 않는다. 이 충돌은 실제 라벨 오류가 아니라 관측 정보 부족일 수도 있다. 제외는 실험 설계 선택이며 데이터 오류 수정으로 부르지 않는다.
5. 이후 클래스별 남은 고유 입력 수를 확인하고 동일한 목표 수를 샘플링한다. 부족한 클래스를 복제하여 '고유 표본 수'를 맞추지 않는다. 제외된 클래스·행과 클래스 분포 변화는 보고한다.
6. 확정한 평가 구성: 같은 원본 기록의 복제나 동일 세션을 부적절하게 나눈 것으로 확인된 누수는 방지한다. 다른 시기에 실제 발생한 별개 플로우가 같은 PPI를 가진다는 이유만으로 원본 시간차 평가에서 제거하지 않는다. 전체 평가와 실제 학습 입력 기준의 겹침/비겹침 성능을 별도로 제시한다. 그룹은 라벨과 무관하게 PPI 일치만으로 정한다. 전체 평가 집합은 같은 서비스 구성의 모델·seed·표본 수 사이에서 공통으로 사용한다. 실행별 겹침 그룹은 같은 seed·표본 수의 M0~M5에서 공통이며 seed·표본 수가 바뀌면 달라질 수 있다. 반복과 라벨 수 사이의 공통 미관측 평가도 아래 정의대로 유지한다. 개발셋의 자연 반복 유지 여부는 실행 manifest에 명시한다.
7. 평가셋 내부에 라벨 충돌이 있거나 모델이 틀렸다는 이유로 해당 기록을 주 평가에서 제거하지 않는다. 충돌 그룹의 수·성능을 별도로 보고할 수 있다.
8. M0~M5는 같은 정제·샘플링 manifest를 사용한다. M0 통계 표현이 다른 PPI들을 같은 통계값으로 요약할 수 있으나, M0에만 별도의 라벨 기반 정제를 적용하지 않는다.

중복 키는 모델에 들어가는 결정적 전처리 이후의 PPI 3×30 값이다. 원본 ID, 라벨, FLOWSTATS를 키에 포함하지 않는다. 허용 구간 절단·단위·채널 순서·패딩 처리를 고정하고, 해시로 후보를 찾더라도 실제 값의 일치를 확인한다. 근사한 패턴까지 임의의 반올림으로 합치지 않는다.

재검토 이력: 최초 제안은 원본 주 평가 + 미관측 입력 보조 평가였고, 후속 응답에서 미관측 입력을 주 평가로 성급히 확정했다. 사용자의 '안 넣는 게 맞나, 넣는 게 맞나' 질문으로 재검토했고, 이어진 '그렇게 가자' 답변으로 원본 주 평가 + 미관측 보조 평가에 동의했다. PPI 값의 동일성과 동일 원본 기록·세션의 누수는 구분해야 한다. 향후 실제 트래픽 성능이 목표라면 자연 반복을 유지한 시간차 평가가 그 질문에 더 맞고, PPI 미관측 부분집합은 새로운 패턴에서의 성능을 측정한다. 중복 제거는 더 정확한 평가를 자동 보장하지 않고 평가 대상 분포를 바꾼다. 두 결과는 같은 모델의 예측에서 산출할 수 있어 별도 재학습이 필요하지 않다.

근거: [When Simple Model Just Works, §V-A](https://arxiv.org/html/2506.08655v1#S5.SS1)는 실제 사용에서 자연 발생한 반복과 평가 설계가 만든 중복을 구분하고 시간순 분할을 논의한다. 여기서 미관측은 이번 재실험의 학습·개발 기준이며, 과거 모든 실험이나 공개 사전학습 원천 데이터와의 중복 부재를 보장하지 않는다. 현재 감사는 입력 충돌을 확인했으며 동일 세션의 재수록 여부까지 증명하지 않았다.

짧은 플로우는 30까지 패딩하는 방식이 기본 후보이며, 중복을 줄이기 위해 실제 30패킷 미만을 전부 제거하는 것은 별개의 선택 편향을 만들 수 있다. 길이별 결과를 함께 보는 편을 권고한다. 실제 길이 제한은 사용자 확정 전 적용하지 않는다.

### 4.1 평가 결과를 겹침 여부로 나누어 보여주는 규칙 — 사용자 요청 반영

| 결과 | 해당 월 평가 표본의 범위 | 해석 |
|---|---|---|
| 전체 | 사전에 정한 시간차 평가 전체 | 자연스러운 반복을 포함한 실제 평가 분포의 성능; 주 결과 |
| Train-overlap | **그 실행에서 실제 학습에 쓴** PPI와 정확히 같은 입력 | 이미 본 입력 패턴이 다른 플로우에서 재등장할 때의 성능 |
| Train-nonoverlap | 그 실행의 실제 학습 PPI 어디에도 없는 입력 | 해당 모델이 학습에 사용하지 않은 PPI 패턴에서의 성능 |
| Common-unseen | 사전에 확정한 같은 과제의 전체 seed·예산 학습 manifest 합집합과 공통 검증 집합 어디에도 없는 입력 | 모델·표본 수·반복 간 동일한 미관측 평가 집합을 유지하는 보조 비교 |

- 겹침은 공통 입력 계약(단위·clipping·채널·패딩 고정)의 PPI 3×30 값으로 판정한다. 라벨이나 원본 ID는 입력 키에 넣지 않는다. 학생의 학습된 변환·교사의 내부 IPT 구간화·M0 요약 통계로 각각 다른 겹침 기준을 만들지 않는다. 해시 후보의 실제 배열 일치를 확인한다.
- 학습 flow의 원본 ID가 평가에 들어간 경우는 이 겹침 실험에 허용한 표본이 아니라 분할 오류다. 학습 flow를 테스트에 복사해서 겹침 그룹을 만들지 않는다. 평가 라벨이 학습 라벨과 달라도 입력이 같으면 Train-overlap에 포함한다.
- Train-overlap과 Train-nonoverlap은 전체 평가를 빠짐없이 둘로 나눈다. 50개 조건의 키에는 실제 사용한 50개만 넣고, 아직 학습하지 않은 같은 달 후보 전체나 1,000개 풀을 넣지 않는다.
- Train-nonoverlap 중 검증셋에는 나타난 입력이 있을 수 있다. 검증 겹침 수를 별도로 기록하고 '학습·검증 모두 미관측'이라고 부르지 않는다. Common-unseen의 키 합집합과 평가 ID 목록은 테스트 점수 확인 전에 고정한다.
- 각 결과에 표본 수·전체 대비 비율·클래스별 support·Macro-F1·Accuracy를 함께 제시하고 같은 그룹 내 M5−M3/M5−M4를 비교한다. Macro-F1은 기존의 고정 클래스 목록 기준이며 부재 클래스를 함께 표시한다. 그룹 자체가 비어 있으면 성능은 N/A로 보고한다.
- 월별로 따로 계산하고 반복의 평균·표준편차를 보고한다. 실행별 겹침 부분집합은 seed·예산에 따라 달라질 수 있음을 설명한다. 서로 다른 그룹의 Macro-F1을 표본 비중으로 평균해 전체 Macro-F1을 만들지 않는다.
- 같은 모델의 평가 예측을 나누어 계산하는 분석이다. 겹침용·비겹침용 모델을 따로 재학습하지 않는다. 높은 겹침 성능만으로 암기라고 단정하거나, 비겹침 성능을 완전히 새로운 서비스의 인식 성능으로 해석하지 않는다.

## 5. 계획서 대조: 실행 전에 고정하거나 조정할 항목

원문: `../../reports/2026-10-26_planned_experiments/plan_source.txt`, 특히 2.3~3.7절. 다음은 새 학습을 실행했다는 뜻이 아니다.

### 대표 비교와 표본 수

- 원래 계획서의 대표 조건은 **클래스당 200개, 2025년 4월 평가, 5회 반복**이다. 주 비교는 M5−M3, 보완 비교는 M5−M4이며 M2−M1로 사전학습 효과를 확인한다.
- 최신 실행 순서는 **Google 포함 20개: 200 → 50 → 100 → 1,000개/클래스**다. 200개에서 M0~M5 × 5회 = 30회, 네 표본 수 전체는 120회다. 이후 세 조건을 추가하는 횟수는 90회이며 200개 조건을 다시 중복 계산하지 않는다. 원래 계획서의 90회에서 100개 조건 30회가 추가된 것이다. 입력 제거 실험·설정 탐색은 별도이고, 후속 서비스 구성의 전체 실행 횟수는 아직 확정하지 않았다.
- 사용 서비스 목록은 감사 manifest의 `google_included20` 목록을 기준으로 한다. 이는 원래 계획서의 '1월 유효 표본 1,000개 이상 서비스 중 빈도 상위 20개'와 다른 구성이다. 서비스 목록과 선택 이유를 명시하고, 후속 구성과의 점수 차이를 Google 포함 여부 하나의 인과 효과로 단정하지 않는다.
- **1월 유효 PPI에서 같은 라벨 중복과 해당 구성 내 교차 라벨 충돌 그룹을 제거한 뒤에도 고유 입력 1,000개 이상 확보 가능한지 확인한다.** 기존 감사 집계상 Google 포함 20개는 모두 충족하고, Google 미포함 후보에서는 13개가 충족한다. Google 미포함은 정제 전 유효 행 1,000개 이상인 후보도 14개뿐이며, Outlook은 같은 라벨 내부 고유 PPI가 909개여서 제외된다. 현재 XS 1월 자료와 제외 규칙으로 Google 미포함 20개를 채울 수 없다.
- 위 자격 판정은 `raw_by_service.csv`의 같은 라벨 고유 패턴 수에서 충돌 **행** 수를 전부 빼도 1,000개 이상인지 확인한 보수적 하한에 근거한다. 불합격은 같은 라벨 고유 패턴부터 1,000개 미만이며 경계 미확정 서비스는 없다. 충돌 제거 후 실제 고유 개수를 재계산한 값으로 부르지 않는다. Google 포함 20개 구성의 최저 하한은 1,154개다. 후보 구성을 바꾸면 구성 내 충돌도 다시 산정한다.
- 후속 1은 Google 미포함 별도 비교다. 같은 1,000개 자격 기준을 유지하면 현 자료에서 13개가 가능하다. 후속 2는 **Google 계열 중 정제 후 고유 입력 1,000개 이상인 서비스만** 사용하는 비교다. 현재 자격을 충족하는 20개를 `google_only20`으로 구분한다. 처음의 `google_included20`은 다른 제공자의 서비스도 포함한 혼합 구성이다.
- Google 계열 후보 24개에서 Chrome Remote Desktop(같은 라벨 고유 PPI 50개), Colab(106개), Conncheck(161개), Pay(675개)를 학습 기간의 자격 기준으로 제외한다. 이후 평가 정확도나 미래 월 라벨을 보고 제외한 것이 아니다. 원래 24개 대상 감사 결과는 그대로 보존하며 새로운 학습 manifest만 별도로 만든다.
- `google_only20` 후보 목록: google-www, google-play, google-services, google-gstatic, google-usercontent, google-authentication, google-fonts, google-drive, google-docs, google-photos, google-translate, youtube, google-hangouts, google-ads, google-safebrowsing, google-recaptcha, google-imasdk, google-calendar, google-autofill, firebase-crashlytics. 기존 24개 전체 구성에서도 이 20개는 충돌 제거량을 보수적으로 잡아 1,000개 초과를 확보할 수 있다. 새 구성의 정제 후 실제 수는 데이터 생성 시 다시 산정한다.
- 같은 반복 안에서는 **50 ⊂ 100 ⊂ 200 ⊂ 1,000**으로 표본을 중첩하고 M0~M5가 같은 표본을 사용한다. 2월 검증 집합은 공통으로 유지한다. 학습 정답뿐 아니라 검증·정제에 접근한 정답 범위도 공개한다. 세 과제 모두 원천 표본이 풍부한 서비스에서 목표 학습 라벨을 제한한 비교이며, 제외한 희소 서비스까지 대표하지 않는다.

### 모델·학습 통제

- M1/M2의 분류 구조와 M3/M4/M5의 학생 구조를 각각 동일하게 고정한다. 계획서 학생은 Conv1D 채널 32→64→64, 커널 3, 마스크를 적용한 평균 집계와 분류층이다. 2026-10-28 독립적인 CPU 구조 확인용 인스턴스에서 **20클래스 20,180개**를 확인했다. 이는 새 학습 코드 통합이나 학습 완료를 뜻하지 않는다. 과거 약 5만 파라미터 학생을 자동 재사용하지 않는다.
- 교사 경로의 정확한 구분: 앞선 권고안은 공개 backbone의 feature refinement(Linear448+BN+ReLU)까지 포함해 20클래스 897,641개였다. **원 논문 §V-A를 재확인하니 전이실험은 pooling 이후·refinement 이전 448차원 특징을 사용한다.** 논문 전이 구조에 맞춘 새 권고안은 refinement를 제외하고 Linear(448,C)를 붙이는 경로이며 20클래스 **695,593개**다. 두 경로 모두 공개 모델 계열이지만 원 논문 실험과 완전히 같다고 혼용하지 않는다. 이는 구조 선택의 권고 수정이고 아직 학습 코드 변경·실행은 하지 않았다. 최종 실행 manifest에서 경로를 하나로 고정한다.
- 공식 무가중치 생성자의 PLE 임베딩은 데이터 비의존 초기화이므로 M1을 '모든 가중치를 순수 난수로 초기화'했다고 설명하지 않는다. 논문의 BN 처리·학습 일정·정규화 기법과 데이터까지 그대로 재현하는 실험이라고도 주장하지 않는다. 세부 근거와 두 경로의 수치는 `model_structure_review.md`, `model_structure_check.json`에 기록했다.
- 학생 3층 CNN은 현재 비교 기준안이며 최적 구조로 검증되지 않았다. 비교할 가치가 큰 대안은 비슷한 파라미터 예산의 작은 residual/dilated CNN(TCN 아이디어 적용)이다. depthwise separable CNN이나 GRU도 가능하다. 먼저 200개 조건의 직접학습 학생과 2월 검증·CPU 비용으로 소수 후보를 비교한 뒤 선택한 구조를 M3~M5에 공통 적용하는 방안을 권고한다. 후보별 새 학습은 아직 실행하지 않았고 전체 실험 조합에 자동 추가하지 않는다.
- M3~M5는 같은 반복에서 동일한 초기 가중치·학습 데이터·기본 학습 일정으로 비교한다. 손실 이외에 학생 구조나 데이터량까지 바뀌지 않게 한다. 모델군별 튜닝 범위와 계산 예산은 사전에 정하고 검증셋으로 선택한다.
- M4/M5는 동일한 목표 학습 표본의 실제 정답과 교사 확률을 사용한다. 증류 중 교사는 고정하고, 온도·손실 비중·최적 checkpoint 선택은 2월 검증으로 한다. 이전 실험의 추가 무라벨 데이터나 의사 라벨 확대를 이번 기본 비교에 섞지 않는다.
- M0는 같은 첫 최대 30패킷으로 계산한 통계만 사용한다. 신경망의 PPI 텐서를 그대로 입력하는 모델과는 표현이 다르므로, 통계 특징 목록·유효 패킷 마스크·계산 비용을 명시한다.
- 각 모델에 맞는 전처리를 고정하고, 학습 표본에서만 정규화 통계를 구한다. 전처리·채널 제거 전에 실제 길이 마스크를 보존한다. 실제 0ms IPT를 패딩으로 오인하지 않는다.

### 입력 근거·성능·실행 비용

- 계획서 2.3절에는 클래스당 200개에서 직접학습 학생 M3를 사용해 **SIZE+DIR+IPT 전체, SIZE 제외, DIR 제외, IPT 제외**를 비교하는 입력 기여도 점검이 있다. 제외 조건은 각각 재학습하고 공통 검증에서 비교한다. 공개 교사에 채널을 갑자기 지워 평가하는 실험과 구분한다. M0~M5 기본 비교 후 우선할 작은 추가 항목이며, FLOWSTATS 확장과 별개다. 이번 사용자 메시지만으로 새 실행 횟수나 중간평가 필수 범위를 추가 확정하지 않는다.
- Macro-F1을 주 지표로, Accuracy·서비스별 결과·혼동행렬·5회 평균과 표준편차·같은 반복별 M5−M3/M5−M4 차이를 보고한다. Google 포함 구성은 Google 서비스끼리의 혼동도 따로 확인한다.
- 4월 대표 평가와 5월 시간 변화 평가를 구분한다. 이미 과거 실험에서 본 월들이므로 완전히 처음 보는 최종 테스트라고 부르지 않는다. 이번 설정 선택은 2월로 제한한다.
- 계획서는 정확도뿐 아니라 같은 CPU·스레드·정밀도에서 batch 1 지연 중앙값/p95, 처리량, 메모리, 모델 크기·파라미터 수를 요구한다. 전처리·모델 연산·패킷 관측 대기시간은 구분한다. 동일 입력의 예측과 실행 시간을 보여주는 작은 시연도 계획 범위다.
- M5가 M3보다 좋지 않더라도 비교는 유효하다. M0 또는 M3로 충분한 조건과 추가 사전학습·증류 비용 대비 이득이 없는 조건도 결론으로 보고한다.

## 6. 중간평가 계획 완성도 점검

2026-10-28 사용자 질문 '중간평가까지 계획은 끝인가, 놓친 것은 없는가'에 대한 점검이다. **핵심 연구 질문과 비교 범위는 충분하지만, 최종 실행 명세와 신규 학습 파이프라인은 아직 완성되지 않았다.** 추가 모델·연구 질문을 계속 늘리는 단계로 해석하지 않는다.

| 남은 항목 | 실행 전 완료할 내용 | 현재 상태 |
|---|---|---|

- **라벨 예산:** '50개/클래스'는 해당 모델 fitting에 사용한 학습 라벨 수다. 별도 2월 검증 라벨, 200개 조건을 이용한 학생 구조 선택, 1월 라벨 기반 정제·서비스 선정에서 사용한 정답까지 50개에 포함된 것으로 설명하지 않는다. 이 개발용 라벨과 연구 전체의 고유 표본 사용량을 함께 보고한다. 전체 개발 과정에 오직 50개 정답만 주어진 실험을 주장하려면 별도 프로토콜이 필요하며 현재 범위에 자동 추가하지 않는다.
- **비교 공정성:** M1/M2의 구조, M3/M4/M5의 구조·초기값, 같은 반복의 실제 학습 표본을 맞춘다. 학습 일정 상한과 설정 탐색 예산을 먼저 정한다. M2에만 별도 BN 고정·정규화·학습률 절차를 적용한다면 그 차이도 명시하고, 결과를 초기 가중치 하나의 효과라고 단정하지 않는다. KD 교사는 같은 서비스·라벨 예산·seed의 checkpoint를 사용한다.
- **평가 해석:** 학습은 클래스별 균등 표본, 주 평가는 해당 월의 원래 서비스 분포를 유지하는 원칙이다. Google 미포함 13개와 혼합/Google 계열 20개의 총점 차이는 Google 포함 여부 하나의 효과가 아니다. 월별·그룹별 support와 5회 반복별 차이를 함께 제시한다. 4·5월은 과거에 이미 본 자료이므로 완전 미사용 최종 테스트로 부르지 않고, 이번 설정 선택은 2월에 한정한다.
- **비용 해석:** 경량성의 주 결과는 같은 CPU에서 측정한 추론 비용이다. 교사 적응 학습, 증류용 교사 예측, 학생 학습에 든 시간도 별도로 기록하여 추가 학습 비용을 숨기지 않는다. 작은 실제 실행으로 일정을 산정하고 체크포인트와 재개 정보를 보존한다. 구조 파라미터 수만으로 실제 CPU 속도나 학습 종료 시각을 예측하지 않는다.
- **중간발표 우선순위 권고:** 먼저 혼합20·200개 조건의 M0~M5 × 5회 = 30회와 그 결과 분석을 완성한다. 이어서 합의한 50→100→1,000개 확장과 Google 미포함·계열 구성으로 진행한다. 이 권고는 후속 실험을 취소하거나 사용자 승인 범위를 줄이는 것이 아니다. 계획서의 중간발표 날짜는 11/11, 자료 제출은 11/10이며, 실제 마감 변경은 별도 확인 사항이다. 코드만 구현된 상태와 120회 결과가 확보된 상태를 구분해서 보고한다.
- **결론 기준:** M5가 M3보다 좋지 않아도 통제가 지켜진 비교는 유효하다. 모델이나 결과가 불리하다는 이유로 삭제하거나 탐색을 계속해 유리한 설정만 남기지 않는다. 교사 대비 성능 손실·직접학습 대비 차이·CPU 비용을 함께 보고하고, 실패한 실행도 실패 원인과 처리 내역을 남긴다.

완료 판단: 위 실행 명세를 고정하고 짧은 실제 학습 연결 확인을 통과하면, 현재 범위의 중간평가 실험을 진행하기에 충분하다. 지금 단계에서 최적 모델·성능 향상·모든 잠재 문제의 부재가 검증되었다고 말하지 않는다. 이번 점검으로 새 학습이나 추가 유료 실행을 시작하지 않았다.

### 8.2 이번 선택의 적용 원칙

- 짧은 플로우를 중복 감소 목적으로 일괄 삭제하지 않는다. 원래 유효 패킷 마스크를 보존하며, 실제 IPT=0을 패딩으로 취급하지 않는다.
- 고정된 변환의 수식·clipping·단위는 실행 명세에 명시해야 한다. 원문은 SIZE 고정 나눗셈·IPT 로그 변환을 추천했지만 특정 분모·상한 숫자까지 정하지는 않았다. 기존 구조 검토의 `SIZE/1500`, `log1p(IPT)/log1p(65000)`은 활용 가능한 구현 후보이며, 원문에 적힌 확정 수치라고 설명하지 않는다.
- M2 전체 미세조정은 backbone까지 학습하되 **BN running statistics는 유지**한다. BN의 affine 가중치까지 모두 동결하거나 전체 backbone을 eval/동결하는 것으로 혼동하지 않는다. 학습 루프의 train() 호출 뒤에도 BN 통계 정책을 유지해야 한다.
- 학생 B안 비교는 현재 필수 학습 수에 자동 추가하지 않는다. 계획서 기본 모델 비교를 우선한다.
- KD는 기존대로 같은 과제·라벨 수·반복에 맞는 M1/M2 교사를 사용한다. 교사는 증류 중 고정하며 M3/M4/M5의 구조·초기값·기본 학습 조건을 맞춘다.
- α={0.1,0.25,0.5}, T={1,2,4}로 3개 α × 3개 T = 교사별9개, 두 교사 합계 **개발용 seed당 학생 학습18회**다. 교사 학습·다른 설정 탐색·본 실험5회 반복은 이 수에 포함되지 않는다.
- 후속 12~14번 선택에 따라 M4/M5는 **공통 α·T**를 사용한다. 개발용 반복은 **2회**, 대표 혼합20·200개 조건에서 고른 설정을 중간발표의 다른 라벨 수와 후속 서비스 구성에도 유지한다. 세부 선택 규칙은 §8.3을 따른다.
- α=0 직접학습은 M3 기준 모델로 유지하며 KD의 3개 α 후보에는 포함하지 않는다. 학생 입력은 PPI뿐이고 GT·교사 확률은 손실에만 사용한다. 기본 손실은 `(1−α) CE(student_logits, y) + α T² KL(softmax(teacher_logits/T) || softmax(student_logits/T))`다.

**KD 탐색·설정 재사용**

- 각 (α,T) 후보의 선택 점수는 개발용 2개 seed에서 얻은 M4·M5의 **학생 검증 Macro-F1 네 값의 산술평균**이다. 교사 자체의 성능이나 4·5월 평가 성능으로 선택하지 않는다.
- 후보는 교사별 9개이며, 개발용 2회로 두 교사의 학생을 학습하면 **2교사 × 9조합 × 2회 = 36회**다. 교사 적응 학습, 다른 설정 탐색, 본 실험은 별도다. 같은 개발용 교사 checkpoint는 해당 9조합에서 재사용한다.
- M3에도 §8.1의 3개 LR 후보 탐색 기회를 주고 학생 기본 설정을 고정한다. KD만 추가로 튜닝한 비용을 숨기지 않는다.
- 중간발표 범위에서는 200개 조건에서 고른 설정을 유지한다. 따라서 라벨 수별·서비스 구성별 최적 성능을 찾았다고 주장하지 않는다. 이후 구성별 재탐색은 별도 후속 작업이다.
- '50개/클래스'는 fitting에 사용한 정답 수다. 대표 200개 조건과 별도 검증 데이터로 설정을 개발한 사실을 함께 공개한다.

**비용 측정·장비**

- 동일 로컬 CPU, 단일 스레드, 신경망의 공통 수치 정밀도, 준비 실행 후 측정을 기본으로 한다. 주 결과는 batch 1 지연 중앙값·p95, 보조 결과는 묶음 처리량이다. 파라미터 수·파일 크기·메모리도 함께 기록한다.
- 관측 대기시간, 입력 전처리 시간, 모델 연산 시간을 구분한다. M0의 첫 최대 30패킷 통계 계산 비용도 포함한다. 저장된 입력에서 잰 모델 연산 시간을 실시간 수집부터의 전체 지연이라고 설명하지 않는다.
- 교사 학습, 증류용 교사 예측 생성, 학생 학습의 시간과 장비를 따로 기록한다. 모델 크기만으로 속도·예산·종료 시각을 추정하지 않는다.
- 최종 학습 장비 가용성과 수치 실행 예산은 아직 측정 전이다. 사용자의 추천 수용을 비용 상한 없는 실행이나 A100 전환 지시로 해석하지 않는다.

**입력 제거·발표 우선순위**

- 입력 제거 비교는 대표 200개 조건의 M3에서 전체 PPI, SIZE 제외, DIR 제외, IPT 제외를 비교한다. 제외 조건마다 처음부터 재학습하며 공통 표본·반복별 초기값·유효 패킷 마스크를 유지한다. 제거 채널을 일정한 값으로 처리하여 구조·파라미터 수를 유지한다.
- 전체 PPI M3의 5회 본 실험 결과가 동일 조건이면 재사용하며, 제외 3조건 × 5회 = 추가 15회다. 이는 여유가 있을 때의 추가 범위이고 필수 대표 30회에 자동 합산하지 않는다.
- 우선순위: **혼합20·200개 M0~M5 × 5회와 분석 → 혼합20의 50·100·1,000개 확장 → 여유 시 입력 제거 → Google 미포함/Google 계열 구성**. 학생 B안은 기존 사용자 지시대로 여유 시 또는 중간발표 이후다.
- 대표 산출물은 성능 평균·표준편차, 반복별 M5−M3/M5−M4, 전체/학습 입력 겹침/비겹침 및 공통 미관측 평가, CPU 비용, 서비스별 혼동, 재현 자료다. 성능이 개선되지 않은 결과도 보존한다.
- 대표 본 실험 30회, 혼합20 네 라벨 수의 전체 본 실험 120회라는 수는 개발용 탐색을 포함하지 않는다. 후속 서비스 구성은 완료한 범위를 구분하여 보고한다.
- 발표 약 3일 전 새 탐색 시작을 중단하고 분석·자료 작성 시간을 확보한다. 기존 계획서에는 11/11 발표·11/10 자료 제출로 적혀 있지만 현재 일정과 동일한지는 아직 확인 전이므로 특정 날짜의 자동 중단을 예약하지 않는다.

### 8.4 실행 전 남은 작업 — 원문 누락은 해결, 구현·측정 단계

- **사용자에게 재결정을 요구할 원문 누락은 없다.** A/B 구조, BN/GeM, LR 후보·배치·AdamW, 검증 수, checkpoint 선택, α/T 후보, M0 특징·탐색 후보까지 승인과 연결했다.
- 원문에도 숫자가 없던 사항은 구현 기본값으로 명시한다: 개발용2개/본 실험5개 seed의 실제 번호와 검증 추출 seed, 고정 변환 상수·clipping, warm-up 길이·감소 함수, AdamW weight decay 등 세부값, LightGBM의 나머지 고정값, 세부 측정 반복 수. 사용자에게 모든 숫자를 다시 고르게 하거나 기존 승인이 없는 것으로 취급하지 않는다. 구현 기본값임을 구분하여 실행 설정에 기록하고 모델군 내 통제를 지킨다.
- 50 epoch는 **개발 시작 후보**이며 아직 검증된 최종 학습 길이가 아니다. 개발 곡선으로 공통 상한을 정한 뒤 본 실험 전에 고정한다. 본 실험 중 유리한 결과를 만들려고 특정 모델만 연장하지 않는다.
- 이후 실행 승인으로 실제 manifest 생성, 짧은 CPU 학습·저장/복구·검증 연결 확인과 로컬 시간·프로세스 메모리 측정은 §9처럼 완료했다. T4 실측과 최종 캠페인 예산 산정은 아직 남아 있다.
- 현재 발표·자료 제출 날짜는 별도 확인 사항이다. 과거 계획서 날짜를 현재 확정 일정으로 간주하지 않는다.
- 이번 작업은 설명 원문 보존과 결정 기록 복원이다. 새 데이터 생성·학습·GPU 실행을 완료한 것으로 표현하지 않는다.

저장·재개 정보, 데이터/체크포인트 해시, 오류 기록, 공통 평가 목록 등은 확정 설계를 재현하기 위한 구현 사항이다. 별도의 모델 연구나 무제한 실험 탐색으로 늘리지 않는다.

## 9. 2026-10-30 실행 준비 및 짧은 CPU 연결 점검 완료

사용자의 'ㅇㅇ 진행해' 지시에 따라 [새 실행 폴더 — 원본 로컬 보관](../../../PUBLICATION.md#omitted-artifacts)에 설정과 코드를 구현했다. **이는 개발 탐색이나 본 실험의 성능 결과가 아니다.**

- 실제 설정: `../2026-10-30_midterm_restart/config.json`. 구현 기본값은 개발 seed101/102, 본 실험201~205, 검증 추출20261030, student `SIZE/1500` 및 `log1p(IPT)/log1p(65000)`, AdamW decay1e-4, warm-up5 epoch 후 cosine 감소 등이다. 원문에서 최적값으로 정해진 것이 아니라, 수용한 설계 안에서 재현 가능하게 명시한 기본값이다.
- 학습은 CPU2스레드로 연결 점검했고, CPU 추론 비용은 단일 스레드로 측정했다. Colab을 연결하거나 GPU를 할당하지 않았다.
- 3개 구성의 정제 후 실제 고유 입력은 혼합20 **560,745개**, 미포함13 **222,826개**, Google 계열20 **450,027개**다. 클래스별 최저는 각각 **1,173 / 1,858 / 1,034개**로 모두1,000 조건을 충족한다. 기존의 보수적 하한 추정과 달리 실제 정제 결과다.

- 원본 HDF5 해시 일치, 캐시와 원본48개 기록 대조, 파일별 해시, 실제 학습 입력의 고유성·균등·중첩·원본 ID 분리, 평가 마스크의 다른 계산 방식 대조가 통과했다.
- 성공한 연결 실행은 `smoke_v2`다. 혼합20·클래스당50개(총1,000개), 검증 클래스당10개(총200개), 신경망2 epoch/M0최대20 round만 실행했다. M4/M5의 α0.25/T2는 점검용 한 조합이며 선택 완료된 설정이 아니다.
- M0~M5 입력·학습·저장·검증 예측이 통과했다. M3/M4/M5 초기 state가 같고, 여섯 모델의 학습 ID가 같았다. M1 BN은 갱신, M2 BN 통계는 유지됐다. 중단 없이 수행한 다음 업데이트와 optimizer/scheduler/RNG를 복구한 다음 업데이트의 손실·전체 state가 정확히 같았다.
- 공식 패키지의 보조 packet-size histogram 카운터가 CPU의 `histc(Int)` 미지원으로 첫 실행을 중단시켰다. 이번 프로토콜에서 입력·손실에 쓰지 않는 보조 카운터만 비활성화했다. 구조·GeM·학습 파라미터는 유지했고 원본 checkpoint도 변경하지 않았다. 실패 기록을 보존했다.
