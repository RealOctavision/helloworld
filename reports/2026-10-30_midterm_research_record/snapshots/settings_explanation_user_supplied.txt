- 최대 pooling: 가장 강한 반응을 선택.

현재 추천은 공개 모델의 GeM 구조를 유지하고, pooling 종류까지 탐색하지 않는 것이야. 조절 파라미터의 학습 여부도 양쪽에서 명시적으로 맞춰야 해. 기본 학습 가능 상태를 유지한다면 M1은 기본 초기값, M2는 공개 체크포인트의 값을 출발점으로 사용해.

선택	의미	장단점
원래 숫자 사용	별도 크기 조절 없음	단순하지만 학습이 어려울 수 있음
고정된 변환 사용	크기는 일정 값으로 나누고, 시간은 로그 변환	실행마다 동일하고 미래 데이터의 통계를 참조하지 않음
학습셋 평균·표준편차로 표준화	해당 학습 데이터 기준으로 변환	적응적이지만 실행별 변환이 달라지며 통계 계산 범위를 관리해야 함


학생에는 고정 변환을 추천해. 후보는 크기를 고정 기준으로 나누고, 시간에 log(1+시간)을 적용하는 방식이야. 교사는 공개 모델이 요구하는 입력 단위와 내부 변환을 유지해야 해.

같은 원본 PPI를 보더라도 교사와 학생의 내부 표현까지 같을 필요는 없어. 대신 M1/M2끼리, M3/M4/M5끼리는 동일해야 해.

그리고 실제 IPT가 0인 패킷을 패딩으로 오인하면 안 돼. 유효 패킷 마스크는 변환 전에 보존해야 해.
7. 검증 데이터: 서비스당 몇 개를 사용할까?

학습 데이터는 답을 보고 배우는 자료이고, 검증 데이터는 어떤 설정과 체크포인트를 선택할지 결정하는 자료야.

검증 표본이 너무 적으면 설정을 잘못 고를 가능성이 커지고, 너무 많으면 개발에 사용한 정답 수와 평가 비용이 늘어나.
선택	혼합20 기준 크기	특징
서비스당 50개	1,000개	가볍지만 서비스별 결과 변동이 클 수 있음
서비스당 100개	2,000개	비교적 작은 공통 검증셋
서비스당 최대 200개	최대 4,000개	표본을 더 확보하면서 크기를 제한
2월 전체	서비스마다 다름	많은 자료를 사용하지만 빈도 편차와 평가 비용이 커짐


여기서 실제 자료를 확인하니:
- 혼합20의 2월 유효 기록 최소는 Google Drive의 598개.
- Google 계열 후속 구성에는 Google Hangouts가 133개인 경우가 있어.
이 값은 기존 감사의 유효 기록 수이고, 새 검증 목록을 생성한 결과는 아니야.

그래서 “모든 구성에서 무조건 200개씩”은 적용할 수 없어.

내 추천은:
2월에서 서비스당 최대 200개를 고정 추출하고, 부족한 서비스는 사용 가능한 기록을 모두 사용한다. 복제해서 수를 채우지 않는다.

이 경우 후속 구성의 검증셋은 완전 균등하지 않으므로 서비스별 표본 수도 공개해야 해. 완전 균등이 더 중요하다면 서비스당 100개로 통일하는 선택도 가능해.

추출할 때는 월초 기록부터 200개를 자르기보다, 월 전체에서 고정된 방식으로 뽑는 편이 좋아. 그리고 모든 모델·반복·학습 표본 수에서 같은 검증셋을 사용하자.

검증셋에서도 서로 다른 플로우의 자연스러운 입력 반복은 유지하고 겹침 정도를 기록하는 방향을 추천해. 다만 같은 원본 기록이 학습과 검증에 동시에 들어가는 분할 오류는 막아야 해.

라벨 예산 표현도 여기서 정리해야 해.

서비스당 50개로 학습하고, 검증에 200개를 사용했다면:
“학습 라벨 50개/서비스 조건, 별도 검증 라벨 사용”

이라고 해야 해.

정제·서비스 선정·학생 구조 선택에 사용한 정답도 있으므로 **“연구 전체에서 정답을 딱 50개만 사용했다”**고 하면 안 돼. 정말 전체 정답 예산을 50개로 제한하려면 학습·검증 배분부터 다른 실험을 설계해야 해.

현재 목적에는 학습 라벨 예산과 개발용 라벨을 구분해서 공개하는 방식을 추천해.
8. 학습률·배치·epoch: 무엇을 의미하고 어떻게 고를까?

이 숫자들은 직접 최적값을 맞히려 하기보다, 좁은 후보와 공통 규칙을 정하는 것이 중요해.

학습률은 한 번에 모델을 얼마나 수정할지야.
- 너무 크면: 좋은 값을 지나치거나 기존 지식을 크게 훼손할 수 있음.
- 너무 작으면: 정해진 시간 안에 충분히 배우지 못할 수 있음.
탐색 후보의 예시는 다음과 같아.
모델군	학습률 후보 초안
M1, 처음 학습하는 큰 모델	0.0001 / 0.0003 / 0.001
M2, 사전학습 모델 미세조정	0.00001 / 0.00003 / 0.0001
M3~M5, 작은 학생	0.0003 / 0.001 / 0.003


이 값들이 우리 데이터에서 좋다고 확인된 것은 아니야. 검증으로 고를 후보 범위야.

학생은 먼저 M3에서 기본 학습률을 정하고 M4/M5에도 공통 적용하면 통제하기 쉬워. 대신 “KD에 개별 최적화한 최고 성능”을 찾은 실험은 아니라는 한계가 있어.

배치 크기는 한 번의 수정에 몇 개의 입력을 묶을지야.
배치 크기	특징
64	수정 횟수가 많아지고 메모리 부담이 작음
128	우선 확인하기 좋은 절충 후보
256	수정 횟수가 줄고 큰 묶음으로 계산


큰 배치가 무조건 빠르거나 정확한 것은 아니야. 실제 장치에서 확인해야 해.

추천 초안은 128이고, 실행을 승인한 뒤 작은 연결 점검에서 메모리와 동작을 확인하는 순서가 좋아.

epoch는 학습 데이터를 한 바퀴 보는 것, step은 가중치를 한 번 수정하는 것이야.

혼합20·서비스당 200개면 총 4,000개야. 배치 128이면 한 epoch에 약 32번 수정해.
서비스당 학습 수	전체 학습 수	배치 128에서 epoch당 step
50	1,000	8
100	2,000	16
200	4,000	32
1,000	20,000	157


마지막 작은 배치까지 사용한다는 가정이야.

따라서 같은 50 epoch라도 학습 데이터가 많으면 가중치 수정 횟수도 많아져.

선택지는 다음과 같아.
선택	맞추는 것	해석
같은 epoch	각 표본을 보는 횟수	라벨 수를 늘리며 같은 학습 절차를 적용한 결과
같은 step	가중치 수정 횟수	계산 횟수를 제한했을 때 데이터량 효과
조기종료	검증 개선이 멈추는 규칙	같은 종료 정책 아래의 결과이며 실제 학습량은 다름


현재에는 같은 epoch를 기본으로 하고 실제 step·시간을 함께 보고하는 방식을 추천해. 같은 표본 수 안에서 M3/M4/M5의 업데이트 수를 맞추기 쉬워.

학습 길이는 우선 50 epoch를 후보로 두자. 설정 탐색 단계에서 학습 곡선을 보고 상한을 확정하되, 본실험 도중 특정 모델이 불리하다고 그 모델만 연장하지 않는 게 중요해.

다른 선택으로는 최대 100 epoch, 검증이 15 epoch 동안 개선되지 않으면 종료하는 방식도 있어. 비용을 줄일 수 있지만 모델마다 실제 학습량이 달라져. 처음 통제를 명확히 하는 목적에는 고정 길이가 설명하기 쉬워.

Optimizer는 우선 AdamW 하나로, 학습률은 초기에 완만하게 올렸다가 줄이는 공통 일정으로 제한하는 것을 추천해. Optimizer 종류까지 동시에 탐색할 필요는 없어.
9. 마지막 모델은 어느 시점의 것을 사용할까?

50 epoch를 학습했다고 마지막 모델이 가장 좋은 것은 아니야.

예를 들어:
시점	학습 성능	검증 Macro-F1
20 epoch	계속 좋아짐	0.82
35 epoch	더 좋아짐	0.85
50 epoch	더 좋아짐	0.83


학습 자료에는 더 잘 맞지만 새로운 자료에서는 성능이 나빠질 수 있어.

추천은 2월 검증 Macro-F1이 가장 높은 체크포인트를 선택하는 것이야.
- 주 선택 기준: 검증 Macro-F1.
- 정확히 같으면: 미리 정한 보조 기준 적용. 예를 들어 검증 정답 손실이 낮은 것, 그래도 같으면 이른 epoch.
- 마지막 체크포인트도 따로 저장: 중단 복구와 학습 이력 확인용.
- 4월·5월 점수로 체크포인트를 다시 선택하지 않음.
M1/M2의 교사도 이 규칙으로 선택하고, 학생 학습 중에는 교사를 고정해.

50개 조건의 M5에는 50개 조건에서 학습한 M2를 연결해야 해. 1,000개로 학습한 교사를 연결하면 추가 정답 예산을 활용한 별도 실험이 돼.
10. 증류 비중 α와 온도 T: 선생 말을 얼마나, 어떤 형태로 배울까?

M4/M5는 두 가지 신호를 함께 사용해.
1. 실제 정답: 이 입력의 서비스는 무엇인가?
2. 교사 확률: 교사는 어떤 서비스들을 얼마나 비슷하게 보는가?
기본 손실은 다음이야.
\[
L=(1-\alpha)L_{\text{정답}}
+\alpha T^2L_{\text{교사 확률}}
\]
온도를 사용한 확률 분포와 정답을 함께 사용하는 방식은 기본적인 지식 증류 구성에 해당해. Hinton 등의 지식 증류 논문

α는 교사 확률 손실의 비중이야.
α	의미
0	교사 확률을 사용하지 않음. 다른 조건이 같으면 M3 대조 조건
0.1	정답 중심으로 교사 신호를 조금 추가
0.25	교사 신호를 더 반영
0.5	두 손실에 같은 계수 적용
1	정답 손실 없이 교사 확률만 학습


주의할 점은 α=0.5라고 실제 학습 영향력이 정확히 반반인 것은 아니라는 거야. 두 손실의 수치와 기울기 크기가 다를 수 있어.

T는 교사의 확률을 얼마나 부드럽게 만들지야.

두 클래스만 있는 예를 들면, 교사의 확률이 90% / 10%일 때 T=2를 적용하면 75% / 25%처럼 덜 극단적인 분포가 돼.
- 낮은 온도: 교사의 가장 강한 판단을 강조.
- 높은 온도: 다른 클래스에 대한 상대적 판단도 더 드러남.
- 너무 높은 온도: 구분 정보가 지나치게 약해질 수 있음.
T²는 온도로 달라지는 증류 손실의 기울기 크기를 보정하기 위한 항이야.

선택지는 다음과 같아.
선택	비교량	장단점
α=0.5, T=2 고정	가장 적음	간단하지만 특정 설정에 결론이 좌우될 수 있음
T=2, α=0.1·0.25·0.5 비교	교사별 3개	교사를 얼마나 믿을지 제한적으로 확인
T=1·2·4와 α 3개 조합	교사별 9개	탐색이 넓지만 비용과 검증 적응 위험 증가


추천은 가운데야.

그리고 M4/M5에서 같은 α를 쓸지 따로 고를지도 정해야 해.
- 공통 α: 교사가 바뀌는 효과를 비교하기 쉬움.
- 개별 α: 각 교사에 맞춘 증류 방식의 성능을 비교할 수 있지만 설정 차이가 섞임.
현재에는 공통 α를 추천해. 예를 들어 사전에 “M4/M5의 2월 검증 Macro-F1 평균이 가장 높은 α”를 선택 규칙으로 정할 수 있어.

학생의 입력은 계속 PPI뿐이야. 정답과 교사 확률은 학습 손실에 사용하며, 추론 입력에 붙이는 것이 아니야.
11. M0와 반복 실험에도 고정할 규칙이 있어

M0의 통계 특징은 먼저 목록을 정해야 해.

현재 후보는 첫 최대 30패킷에서 계산하는 16개야.
묶음	특징
개수·방향 4개	유효 패킷 수, 정방향 수, 역방향 수, 방향 전환 수
크기 통계 6개	평균·표준편차·최솟값·최댓값·합·중앙값
시간 통계 6개	평균·표준편차·최솟값·최댓값·합·중앙값


패딩은 제외하고 계산해야 해. 이것은 전체 플로우 통계가 아니라 신경망과 같은 관측 구간의 요약이야.

추천은 이 목록을 기본으로 고정하고, LightGBM의 복잡도를 소수 후보로만 비교하는 것이야. 예를 들어 나뭇잎 수 7·15·31 같은 후보를 둘 수 있어. 숫자가 커지면 복잡한 구분이 가능하지만 적은 데이터에 과적합할 수 있어.

M0에도 같은 검증셋을 사용하고, 특징 추출 시간을 추론 비용에 포함해 별도로 보여줘야 해.

반복 5회는 “좋게 나온 실행을 고르기 위한 것”이 아니야.

각 반복에서 학습 표본 추출·초기 가중치·학습 순서를 바꿔 결과가 얼마나 흔들리는지 보는 거야.

같은 반복 안에서는:
- M0~M5의 학습 표본을 동일하게 사용.
- M3/M4/M5의 초기 가중치를 동일하게 사용.
- 50 ⊂ 100 ⊂ 200 ⊂ 1,000 관계 유지.
- 같은 검증·평가 자료 사용.
결과는 모델별 평균뿐 아니라 같은 반복의 M5−M3 차이도 보여줘야 해.

예를 들어 평균 개선이 0.4%p여도 다섯 번 중 두 번만 좋아진 경우와, 다섯 번 모두 개선된 경우는 해석이 달라져. 다만 5회 반복은 학습 변동을 보는 것이지 독립적인 네트워크 환경 다섯 곳에서 검증한 것은 아니야.
12. 튜닝을 얼마나 할지: 모든 설정을 곱하면 다시 실험이 커져

학생 구조 2개 × 학습률 3개 × 배치 3개 × 온도 3개 × 증류 비중 3개만 해도 162조합이야. 여기에 반복·서비스 구성·라벨 수를 곱하면 감당하기 어려워져.

그래서 무엇을 탐색하고 무엇을 고정할지가 필요해.

현재 추천 초안은:
항목	처리

예를 들어 개발용 seed 1개, 혼합20·200개 조건에서 탐색한다면:
개발 비교	학습 횟수 예시

학생 구조 2개 × 학습률 3개	6

M0 설정 3개	3

이것은 가능한 탐색 예시이지 실행 승인된 목록이 아니야. 또한 M0 한 번과 교사 한 번의 비용은 같지 않아.

선택한 설정을 고정한 뒤 별도의 본실험 5회 반복을 수행하면 돼. 개발용 seed 한 번의 선택에는 우연성이 있으므로, 더 신중하게 하려면 개발 반복을 늘릴 수 있지만 비용도 늘어나.

나는 처음부터 큰 탐색을 하기보다 이 정도의 제한된 탐색과 본실험 5회를 우선하는 편을 추천해.

라벨 수를 바꿀 때도 두 방법이 있어.
- 200개 조건에서 고른 설정을 50·100·1,000개에 공통 적용: 같은 학습 방식에서 라벨 수가 늘어나는 효과를 보기 쉬움.
- 각 라벨 수마다 재튜닝: 조건별 성능을 더 끌어올릴 수 있지만 개발 비용과 해석이 복잡해짐.
현재에는 첫 번째를 추천해. 대신 각 라벨 수의 가능한 최고 성능을 찾았다고 주장하지는 않는 것이야.
13. 성능 외에 무엇을 측정하고, 무엇을 성공이라고 볼까?

우리 목적은 작은 모델을 만드는 것이므로 정확도만으로 끝내면 부족해.

CPU 속도는 같은 장치·스레드 수·정밀도에서 측정해야 해. 파라미터가 적다고 같은 비율로 빨라지는 것은 아니야.

또한 30번째 패킷을 기다리는 시간과 모델이 계산하는 시간은 구분해야 해.

성공 기준도 “M5가 무조건 이겨야 한다”로 두지 말자.
- M5가 M3보다 반복적으로 좋아짐 → 해당 조건에서 증류의 실용적 이득.
- 비슷한 정확도지만 교사보다 훨씬 가벼움 → 경량화 관점에서 의미.
- M3와 차이가 거의 없음 → 이 조건에서는 추가 교사 비용의 필요성이 낮을 수 있음.
- M0가 충분히 좋음 → 간단한 통계 기반 방법의 경쟁력이 중요한 결과.
- 일부 Google 서비스에서만 도움이 됨 → 전체 평균보다 적용 조건이 핵심일 수 있음.
성능 차이가 작고 반복 변동이 크다면, 우열을 강하게 주장하기보다 추가 반복이 필요한 결과라고 설명하면 돼.
