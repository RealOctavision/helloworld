1. 요약
1.1 연구 개요 및 목적
QUIC은 통신 내용을 암호화하여 전송하므로 기존의 Payload 기반 분석만으로는 트래픽의 서비스 및 애플리케이션을 식별하는 데 한계가 있다. 이에 복호화 없이 관측 가능한 패킷의 길이, 방향, 도착 간격 등의 특징을 활용하여 QUIC 트래픽을 분류하는 방법이 연구되고 있으며, 실제 활용을 위해서는 제한된 학습 데이터와 연산 자원에서도 안정적인 분류 성능을 확보할 수 있는지 검토할 필요가 있다.
본 과제는 QUIC 트래픽의 패킷 길이(SIZE), 방향(DIR), 도착 간격(IPT)을 활용하여 서비스를 분류하고, 제한된 학습 데이터와 CPU 기반 실행 환경에서 활용 가능한 경량 분류 모델을 검토하는 것을 목적으로 한다. 이를 위해 공개 사전학습 CNN을 목표 분류 과제에 맞게 미세조정하고, 해당 모델의 출력 정보를 활용하여 소형 CNN을 학습하는 지식증류 방식을 적용한다.
최종적으로 직접 학습한 모델과 사전학습 및 지식증류를 적용한 모델을 비교하여 분류 성능과 실행 비용 측면에서 사전학습과 지식증류의 실효성을 평가하고, 경량 모델을 활용할 수 있는 조건을 도출한다.
1.2 연구 범위 및 사용 환경
본 과제는 목표 서비스에 대한 학습 라벨이 제한적이고, 별도의 GPU 없이 CPU를 이용하여 추론하는 분석 환경을 가정한다. 이러한 조건에서 사전학습 및 지식증류 적용 여부에 따른 분류 성능과 실행 비용을 비교하여 각 학습 방법의 실효성을 평가한다.
학습 데이터 규모에 따른 영향을 확인하기 위해 클래스별 학습 표본을 50개, 200개, 1,000개로 구분하여 비교하며, 서로 다른 시점의 데이터에 동일한 모델을 적용하여 시간 변화에 따른 성능 유지 여부도 함께 평가한다. 연구 범위는 운영망 수준의 시스템 구축보다 학습 방법의 비교·검증과 CPU 환경에서의 경량 모델 실행 가능성 확인에 중점을 둔다.
사전학습이나 지식증류의 우수성을 사전에 전제하지 않으며, 실험 결과를 기반으로 성능 향상과 실행 비용 절감의 실질적인 효과 및 적용 조건을 판단한다.

1.3 자료조사 및 준비 현황
연구 방향과 실험 계획 수립을 위해 현재까지 QUIC 기반 암호화 트래픽 분류, 사전학습 및 전이학습, 지식증류와 경량화에 관한 선행연구를 검토하였다. 또한 연구에 활용 가능한 공개 QUIC 트래픽 데이터와 사전학습 모델, 입력 특징 및 평가 방법을 조사하여 연구 수행에 필요한 기초 조건을 정리하였다.
이를 바탕으로 연구 대상과 입력 특징, 학습 방법 및 비교 실험의 기본 방향을 설정하였으며, 세부 데이터 구성과 실행 환경 등은 연구 초기 데이터 점검 및 구현 과정에서 검증한 후 최종 확정할 예정이다.
2. 기초연구 진행 내용
2.1 QUIC 분류와 사전학습
QUIC은 UDP 기반으로 동작하며 TLS를 통해 통신 보안을 제공하는 전송 프로토콜이다.[1, 2] 본 과제에서는 암호화된 패킷 내용 대신 외부에서 관측 가능한 패킷 길이, 방향, 도착 간격 정보를 활용하여 QUIC 서비스를 분류한다. 동일한 서비스의 트래픽도 수집 시점이나 서비스 제공 환경에 따라 특성이 달라질 수 있으므로, 학습 시점과 다른 후속 시점의 데이터를 활용한 평가도 함께 수행한다.
ET-BERT와 YaTC는 비라벨 트래픽을 사전학습한 후 목표 과제에 맞게 미세조정(Fine-tuning)하는 접근을 제시한다.[10, 11] 반면 본 과제에서는 공개 PPI(Per-Packet Information) 특징과 호환되는 Universal Embedding CNN을 활용하며,[3, 8, 9] 도메인 라벨을 이용해 사전학습된 모델을 목표 서비스 분류 과제에 맞게 미세조정한다.
지식증류(Knowledge Distillation)는 실제 정답과 교사의 예측 확률을 함께 활용하여 학생을 학습하는 방식이다.[4] 학생에게 예측 분포를 제공하는 모델을 교사 모델이라 하고, 그 정보를 참고하여 학습하는 경량모델을 학생 모델이라 한다. 비교 실험에서는 직접 학습한 M1과 사전학습 후 미세조정한 M2를 각각 교사로 사용한다.
2.2 선행연구 분석 및 연구 방향
QUIC 기반 암호화 트래픽 분류와 사전학습, 전이학습 및 지식증류 관련 선행연구를 검토하여 각 연구에서 확인된 주요 내용과 본 연구에서 검증할 사항을 정리하였다.

본 연구는 QUIC 서비스 분류 환경에서 목표 학습 표본 수와 CPU 기반 실행 조건을 설정하고, 사전학습된 교사 모델을 활용했을 때 학생 모델의 분류 성능, 실행 비용 및 후속 시점의 성능이 어떻게 변화하는지를 비교·분석한다. 이를 통해 제한된 학습 데이터와 CPU 기반 실행 환경에서 사전학습과 지식증류의 효과가 나타나는 조건을 비교·분석한다.
2.3 입력 특징의 선정 근거와 확인 계획
본 연구에서는 공개 데이터와 사전학습 CNN에서 공통으로 활용되는 IPT·DIR·SIZE를 입력 특징으로 선정하였다.[3, 7, 8] 기존 연구에서 사용된 특징 정의를 재사용하되, 각 특징이 목표 데이터의 서비스 분류에 기여하는 정도는 별도의 비교 실험을 통해 확인한다.

이 조합은 암호화된 내용을 읽지 않고 사용할 수 있으며 공개 교사의 입력 구조와 호환된다. 특징 선정 시 분류에 제공하는 정보, 수집 가능성, 전처리 비용과 정보 누출 가능성을 함께 검토한다.
도메인 정보는 서비스 라벨 구성과 직접 연결될 수 있고, IP 주소는 특정 수집 환경에 의존한 분류를 유도할 수 있어 입력에서 제외한다. 처음 30개 패킷으로 판단하는 조건에 맞춰, 이후 패킷까지 포함한 전체 flow 통계도 사용하지 않는다.
특징 기여도는 클래스당 학습 라벨 200개와 공통 검증 집합에서 확인한다. 동일한 직접 학습 학생을 다시 학습하여 세 특징을 모두 사용하는 조건과 하나씩 제외하는 조건을 비교한다.
특징 제거 전에 유효 패킷 마스크를 계산하고 전처리 후 해당 채널만 가린다. 유효 패킷·패딩 조건은 동일하게 유지하며, 기본 M0~M5는 처음 최대 30개 패킷의 길이·방향·도착 간격을 공통으로 사용한다.
처음 30개 패킷의 방향 전환 빈도·동일 방향 연속 패킷 수 등 파생 특징 후보도 설계한다. 검증 집합에서 추가 정보와 계산 비용을 평가하고, 신규성은 선행연구와 비교한다. 이 탐색은 기본 90회 비교와 구분한다.


2.4 교사·학생 모델의 초기 구성
교사 모델은 CESNET-QUIC22의 2022년 46주차 도메인 인식 과제로 사전학습 30pktTCNET_256 의가중치를 활용하고, 이를 2025년 목표 서비스 분류 과제에 맞게 미세조정한다.[8] 사전학습 데이터와 목표 데이터 사이에 일부 서비스가 중복될 가능성이 있으므로, 본 연구에서는 이를 미관측 서비스에 대한 인식 성능으로 해석하지 않는다.
학생 모델은 Conv1D·ReLU 블록 3개로 구성하며, 각 블록의 채널 수는 32·64·64, Kernel Size는 3으로 설정한다. 이후 유효 위치에 대한 평균 집계와 선형 분류층을 통해 최종 서비스를 분류한다. Stride·Padding·Dilation은 1로 설정하며, 합성곱층과 분류층에는 Bias를 사용한다.
20개 클래스를 기준으로 한 학생 모델의 초기 설계는 약 20,180개의 파라미터로 구성되며, 이는 현재 단계의 설계값으로 실제 구현 및 측정 결과는 아니다. 학생 모델의 최종 구조는 초기 구현 및 검증 결과를 바탕으로 11월 3일까지 확정하고, 이후 M3~M5 비교 실험에 동일하게 적용한다.
공식 모델 메타데이터 기준 Wrapper는 256차원·1,004,117개의 파라미터로 구성되며, Backbone은 Wrapper의 선형층 및 Batch Normalization 파라미터를 제외하여 계산한 448차원·888,661개이다.[8] 최종 교사 모델의 파라미터 수는 목표 서비스 분류층을 포함한 상태에서 다시 산정한다.
2.5 데이터 조사와 표본 선정 계획
CESNET-QUICEXT-25는 2024년 6월부터 2025년 5월까지 수집된 QUIC 데이터이다. 공식 메타데이터는 서비스 50개와 배경 3개, 가용 flow 194,296,462개를 제시한다. 원 수집은 균일한 1:100 샘플링이며 클래스별로 균형화된 데이터가 아니다. [5, 6, 20]
본 연구에서는 DataZoo에서 제공하는 구성 중 가장 작은 XS 구성(약 1,000만 Flow)을 활용하고, 연구에 필요한 표본을 선정하여 사용한다. 실제 학습에는 서비스별 50개·200개·1,000개의 표본을 사용하며, 20개 서비스를 기준으로 할 경우 최대 20,000개의 학습 표본을 사용한다. 검증 및 테스트 데이터는 학습 데이터와 별도로 구성한다.

3. 최종 목표 설정
3.1 연구 질문과 대표 평가 조건
공개 사전학습이 적은 목표 라벨에서 교사 성능을 높이는지, 그 교사로 증류한 학생이 같은 구조의 직접 학습 학생보다 나은지, 이점이 후속 월에도 유지되는지를 확인한다. 핵심 비교값은 M5와 M3의 Macro-F1 차이이며 M4와의 비교로 교사의 사전학습 여부를 구분한다.
대표 평가 조건은 클래스당 학습 라벨 200개·2025년 4월 테스트로 정한다. 정량 목표는 이 조건의 5회 반복 실험의 평균으로 판단하고 반복별 차이도 보고한다. 서비스별 50개·1,000개 학습 조건과 5월 평가는 효과가 유지되는 범위를 분석한다. 결과를 본 뒤 대표 조건을 바꾸지 않는다.
3.2 전체 학습 구조와 학생 실행

그림 1. 핵심 학습·평가 경로의 개념도. 전체 비교군은 표 5 참조.
학생은 정답을 맞히는 학습과 교사의 서비스별 예측 확률을 참고하는 학습을 함께 진행한다. 정답과의 차이는 교차엔트로피로, 교사와 학생의 예측 확률 분포 차이는 KL 발산으로 계산한다. 예를 들어 교사가 두 서비스를 70%·30%로 예측했다면 그 확률 관계도 학생에게 참고 정보가 된다.[4]
두 학습의 비중과 확률을 부드럽게 만드는 온도 설정은 검증 데이터로 정한다. 학생을 학습하는 동안 교사 가중치는 바꾸지 않고, 같은 목표 학습 표본을 사용한다. 작은 학생 구조의 실행 비용과 증류의 성능 개선 효과를 각각 확인한다.
각 CNN 블록 뒤 패딩을 다시 가리고 유효 위치만 평균 집계한다. 교사·학생의 클래스 순서는 같다. M3·M5는 각각 CPU에서 평가하고 시연에는 선택한 학생 1개를 사용한다. 교사·M0의 비용도 같은 장비에서 측정한다.
3.3 데이터 시기와 학습 표본 수

그림 2. 학습·검증·테스트의 시기와 용도
라벨은 각 통신 기록이 어느 서비스인지 알려주는 정답이다. 학습에는 서비스별 50·200·1,000개의 정답이 있는 기록을 사용한다. 20개 서비스를 선정하면 총 1,000·4,000·20,000개로 학습하는 세 조건이 된다.
2월 검증 표본은 모든 모델·학습 조건·반복에서 같게 사용한다. 한 조건에서 모델을 한 번 개발할 때 사용한 정답 수는 학습용과 검증용을 합쳐 기록하고, 연구 전체의 서로 다른 표본 수는 따로 집계한다. 실제 수집·라벨링 비용을 측정하는 실험은 아니다.

3.5 전처리와 평가 조건
모델별 입력 처리
교사  가중치의 공식 변환을 데이터 경로에서 한 번 적용한다. 유효 SIZE는 1~1,500, IPT는 0~65,000으로 제한하며 스케일링은 하지 않는다.[8] wrapper의 출력 임베딩 정규화와 입력 PPI 전처리는 구분한다.
학생과 기준선  학생 변환은 검증 단계에서 정해 M3~M5에 공통 적용한다. 정규화 통계는 해당 조건의 학습 표본으로만 구한다. 실제 0 ms IPT와 패딩을 구분하고 특징 제거 전 마스크를 유지한다. M0도 처음 30패킷만 사용하며 통계 특징 목록·패딩 제외 규칙은 10/20까지 정한다.
중복과 월별 클래스 차이
초기 데이터 점검에서 중복 처리 기준을 정한다. 시간 분리만으로 세션 독립을 보장하지 않는다. 주 지표는 처음 선정한 서비스 전체의 Macro-F1이며, 표본·예측이 모두 없는 클래스의 F1은 0으로 둔다. 월별 클래스 표본 수와 부재도 보고한다.
클래스 부재의 영향을 구분하도록 4·5월 정답에 공통으로 나타난 클래스의 Macro-F1을 보조 보고한다. 각 월의 전체 예측으로 클래스별 F1을 구한 뒤 공통 클래스만 평균한다.
이 보조 지표는 클래스 재선정·모델 선택에 쓰지 않는다. 월별 차이를 곧바로 모델 성능 저하로 해석하지 않는다.
3.6 성능 지표와 성공 판단
주 지표는 Macro-F1이다. Accuracy, 클래스별 Precision·Recall, 혼동행렬, 5회 반복 실험의 평균·표준편차를 함께 보고한다. M5−M3와 M5−M4의 반복별 차이를 비교하며, 작은 평균 차이만으로 안정적인 이점이라고 결론내리지 않는다.
표 6. 완료 기준과 성능 목표의 구분

구분
판단 기준
최소 완료
M0~M5의 재현 가능한 평가, CPU 시연, 코드·보고서를 제출한다.
증류의 실익
M5가 같은 구조의 M3보다 유리한 학습 표본 수·데이터 시점을 찾고 M4와도 비교한다. 차이가 없으면 추가 학습 비용을 고려한다.
교사 대비 목표
대표 조건에서 M2 대비 M5의 Macro-F1 감소 2%p 이내, 파라미터 5배 이상 축소, CPU 지연 감소를 목표로 한다.
CPU 실행 비용
같은 장비·스레드·정밀도에서 워밍업 후 batch 1 지연의 중앙값과 p95, 처리량·메모리·파일 크기를 측정한다. 모델 실행, 특징 추출·전처리, 패킷 관측 대기시간은 나눠 기록한다. M0·M3로 충분한 경우도 포함해 배포상 선택 이유를 판단한다.
3.7 예상 산출물과 활용
고정 분할·전처리·학습 설정, M0~M5 코드, 공통 평가 결과와 CPU 시연을 하나의 실험 패키지로 정리한다. 사용자는 같은 입력으로 모델별 서비스 예측과 실행 비용을 비교할 수 있도록 한다. 모델 선택에 필요한 라벨 수, 성능 손실, 실행 비용과 시간 변화의 관계를 최종 보고서와 투고용 원고로 제시한다.
시연은 검증된 PPI 특징을 받아 학생의 서비스 예측과 실행 시간을 보여주는 형태로 우선 구현한다. 자체 PCAP 수집은 공개 데이터와 같은 특징 정의를 재현할 수 있을 때 연결하며, 수집 경로의 일치 여부를 별도로 확인한다.
3.8 예상 어려움과 범위 관리
10/8~10/20에는 소규모 표본으로 데이터 읽기부터 모델 호출까지 연결하고, 표본 부족·입력 변환·가중치 호환 문제를 확인한다. 학습 장비, 사용 가능 시간, 저장 공간, 대표 실행의 시간과 메모리도 기록하여 90회 실행과 설정 탐색의 일정을 조정한다.
사전학습이나 증류의 개선이 없으면 입력·학습 조건을 점검하고 검증 집합에서 제한적으로 설정을 조정한다. 이후에도 개선이 없으면 유리하지 않은 조건과 원인을 분석한다. 교사에 가까운 성능만으로 증류가 필요하다고 판단하지 않는다.
선택 확장과 결과 해석
중간발표(11/11) 이후 기본 비교가 안정적으로 동작하고 일정에 여유가 있을 때 30패킷 교사에서 앞 10패킷 학생으로 증류하는 확장을 검토한다. 같은 flow 집합에서 10패킷 학생 직접 학습·10패킷 교사 증류·30패킷 교사 증류를 비교한다. 학생 특징은 10패킷으로 자른 뒤 계산하고 관측 대기와 계산시간을 구분한다.
교사가 실제 30패킷을 본 비교는 패킷 수가 30개 이상인 flow로 한정한다. 선택 확장은 기본 90회에 포함하지 않는다. 일정이 부족하면 확장을 줄이고 기본 비교와 제출물을 우선한다.
결론은 선정 서비스·데이터 기간·실행 환경 안에서 제시한다. 새로운 증류 알고리즘이나 교사 고유 능력의 전달을 입증하는 것이 현재 목표는 아니다. 논문화 과정에서 필요하면 label smoothing 대조군을 검토하되 킥오프 필수 실험에 추가하지 않는다.[19]
4. 개인별 역할
8명이 2명씩 네 개 조를 이루어 병렬로 진행하는 배정안이다. 각 조는 주 담당 업무를 맡되, 실험과 발표 준비에는 전원이 함께 참여한다. 조장은 연구 방향과 결과 통합을, 부조장은 일정과 장비 사용 조정을 함께 맡는다.

4.1 병렬 진행과 공동 작업
초기에는 연구·문서조가 문헌과 비교 질문을 정리하고, 데이터·특징조는 데이터와 입력 형식을 준비한다. 같은 기간 모델·학습조는 공개 모델과 학습 코드를 확인하며, 평가·시연조는 평가 지표 계산과 예측 결과를 보여줄 화면을 준비한다. 공통 입력 형식을 먼저 맞춰 각 조가 따로 작업한 코드를 연결할 수 있도록 한다.
한 조 안에서는 구현과 검토를 나누고 번갈아 맡는다. 실험이 몰리는 시기에는 다른 조도 실행과 결과 확인을 지원한다. 각 조가 담당 내용의 원고를 작성하고 연구·문서조가 통합하며, 발표 준비와 최종 검토는 전원이 함께 진행한다.
4.2 장비와 작업 시간
학습 장비와 CPU 측정 장비는 10/8~10/20 초기 구현 기간에 확인한다. 부조장이 사용 가능 시간과 저장 공간을 조정하고, 모델·학습조와 평가·시연조가 필요한 환경을 함께 정한다. 소규모 실행 시간을 바탕으로 반복 실험을 나누어 배정하며, 개인별 수업 일정과 진행 상황에 맞춰 업무량을 조정한다.
5. 연구 마일스톤
학교에서 배포한 2026-2 마일스톤에 맞춰 기간별 계획을 정리했다. 9월에는 자료조사와 설계를 진행하고, 킥오프 이후 구현·실험을 병렬로 추진한다. 중간발표에서 진행 상황과 보완 계획을 공유하고 최종발표까지 평가와 시연을 마무리한다.

5.1 일정 운영 기준
매주 각 조의 진행 상황과 다음 작업을 공유하고, 중간·최종 발표 전에 결과와 자료를 함께 점검한다. 반복 실험은 장비 사용 시간에 맞춰 분산하며, 일정이 밀리면 기본 비교와 시연을 우선하고 선택 확장은 줄인다.
모델 설정은 검증 데이터로 결정하고 최종 테스트 전에 고정한다. 보고서와 발표자료는 실험과 함께 조금씩 작성해 마지막 주에 작업이 몰리지 않도록 한다.
