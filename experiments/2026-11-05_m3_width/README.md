# M3 채널 확대: 64 → 128 → 128

기존 `32 → 64 → 64` M3의 학습 설정과 표본을 유지하고 채널만 확대합니다.
증류 없이 정답의 cross-entropy로 학습합니다. 20클래스 기준 **77,204 파라미터**입니다.
학습 runner의 범위는 1월 학습·2월 검증이며, 4·5월 평가나 교사 학습을 자동 실행하지 않습니다.
후속 `final_evaluate.py`는 보관된 모델 4개의 4·5월 평가만 별도로 수행합니다.

실제 결과는 [최종 평가 보고서](../../reports/2026-11-08_m3_width_final/README.md)에 정리했습니다.

## Colab에서 실행

1. `M3_width_200_1000.ipynb`를 내려받습니다.
2. Colab의 **파일 → 노트북 업로드**로 엽니다.
3. **런타임 → 런타임 유형 변경 → GPU**를 선택합니다.
4. 새 런타임에서 셀을 위에서부터 실행합니다.
5. 완료 또는 시간 예산 중단 후 마지막 셀에서 결과 ZIP을 내려받습니다.

노트북은 기준 저장소 commit `a78399589391a4807df8ede9ef8205eac9d2e466`을 받고,
내장된 새 코드를 별도 폴더에 저장합니다. 이 변경을 GitHub에 올릴 필요가 없습니다.
공식 HDF5 약 3.54GB를 다운로드·검증하고 기존 준비 코드로 데이터를 재생성합니다.
교사 `.pth` 파일은 필요 없습니다. 디스크 30GB 이상은 계획값이며, 데이터 준비 중
RAM이 부족하면 더 큰 RAM 런타임을 사용해야 합니다.

| 설정 | 값 |
|---|---|
| 서비스 구성 | Google 포함 20서비스 |
| 서비스당 학습량 | 200 / 1,000 flows (총 4,000 / 20,000 flows) |
| 기본 seed | 201, 202: 총 4회 |
| 확장 seed | 201~205: 총 10회 |
| 입력 | 흐름당 첫 최대 30패킷의 IPT·DIR·SIZE |
| 구조 | Conv1d 3→64→128→128, kernel3, ReLU, mask, mean pooling, 20분류기 |
| 학습 | AdamW, lr 0.003, weight decay 0.0001, batch128, 50epoch |
| 스케줄 | warm-up 5epoch + cosine, FP32 |
| 선택 | 2월 검증 Macro-F1 → CE → 빠른 epoch |

200/1,000개는 기존 `main_seed201` 등의 `rank < budget`으로 선택합니다.
따라서 같은 seed의 200개 표본은 1,000개 표본에 포함되고, 기존 A/C와도 일치합니다.
모델이 커지므로 기존 M3와 초기 가중치 자체가 같지는 않습니다. 배치 순서 seed는 같습니다.

## 이미 준비된 저장소에서 CLI 실행

Python 3.12 이상, NumPy, PyTorch, `cesnet-models==0.4.1`이 필요합니다.
데이터 재생성에는 `tables==3.11.1`도 필요합니다. 데이터 준비는 노트북 또는 루트의
`REPRODUCE.md`를 따릅니다. 저장소의 manifest만 있고 NPZ가 없으면 바로 학습할 수 없습니다.

```sh
python experiments/2026-11-05_m3_width/smoke_test.py
python experiments/2026-11-05_m3_width/run.py --dry-run
python experiments/2026-11-05_m3_width/run.py --device cuda --minutes 45
```

각 조건만 따로 실행하거나 5개 seed로 확장할 수 있습니다.

```sh
python experiments/2026-11-05_m3_width/run.py --budgets 200 --seeds 201 202
python experiments/2026-11-05_m3_width/run.py --budgets 1000 --seeds 201 202
python experiments/2026-11-05_m3_width/run.py --seeds 201 202 203 204 205
```

`--minutes`는 한 번 호출의 학습 예산입니다. 데이터 읽기·체크포인트 저장·진단 시간을 포함한
엄격한 청구 상한이나 GPU 자동 해제 기능이 아닙니다. 마지막 완료 epoch의 `last.pt`에서
같은 명령으로 재개합니다. Colab 런타임 삭제 전 결과 ZIP을 보관해야 합니다.
중단 결과를 복원할 때는 ZIP의 `experiments/2026-11-05_m3_width/runs/` 전체를
같은 저장소 위치로 풀고 동일한 코드·데이터·환경에서 실행합니다.
코드·설정·데이터·환경이 달라지면 기존 결과에 이어 쓰지 않고 오류를 냅니다.
계획된 다른 환경 실험에는 `--output`으로 별도 폴더를 지정하세요.

## 결과와 기존 M3 비교

기본 저장 위치는 이 폴더의 `runs/`입니다.

- `summary.json`: 이번 명령에서 요청한 조건의 완료 상태, seed별 학습/검증 F1·정답률,
  기존 M3의 같은 seed·예산 검증 점수, 대응 F1 차이(%p), 예산별 평균·표본 표준편차.
- `M3_wide_s201_n200/metrics.json` 등: 매 epoch 학습 손실·검증 지표, 선택 epoch, 업데이트 수.
- `diagnostics.json`: 검증으로 선택한 체크포인트의 학습 데이터 성능.
- `best.pt`, `last.pt`: 선택 모델과 중단 재개용 모델/옵티마이저/스케줄/RNG.
- `run_context.json`: 채널, 실제 설정, 입력·코드 해시, 실행 환경, 비교 대상 원장.

점수는 JSON에서 0~1 비율이며 `delta_validation_macro_f1_pp`만 %p입니다.
기존 M3 기록이 있으면 클래스·seed·예산·학습률·epoch·학습 표본/입력/라벨 해시와
검증 ID를 대조합니다. 없으면 기존 점수/차이를 `null`로 남기며 다른 조건으로 대체하지 않습니다.
검증 배열 자체는 기존 `prepared/manifest.json`과 해시를 대조합니다.
예산별 평균은 완료된 seed만 사용하므로 반드시 완료 수와 seed 목록을 함께 봅니다.
한 seed만 있으면 표준편차는 `null`입니다.

기존 본실험은 A100, Torch 2.11.0+cu130입니다. Colab의 기존 CUDA PyTorch를 사용하며
`baseline_environment_matches`로 Torch/CUDA/GPU 차이를 표시합니다. 이는 모든 라이브러리의
완전한 환경 동일성을 증명하는 값은 아닙니다. 환경이 다르면 순수한 채널 효과로 단정하지 말고,
필요하면 기존 M3도 해당 환경에서 확인 실행하세요.
50epoch 고정에서 200개는 1,600 updates, 1,000개는 7,850 updates입니다.
데이터량 효과와 학습량 효과가 함께 바뀌는 비교입니다.

## 구현 및 확인 범위

중간발표의 모델·학습·데이터 파일은 수정하지 않았습니다. `WideStudent`가 기존 학생의
전처리·마스킹·forward를 상속하고, `fit_wide`가 호출 중에만 모델 생성 함수를 교체해
기존 학습·체크포인트·평가 코드를 사용합니다. 반환/예외 시 원래 함수를 복원합니다.
후속 runner의 SHA와 실제 설정은 별도 context로 보존합니다. 원본 재현용 검증기에
새 결과를 넣어 원래 M3 결과인 것처럼 취급하지 마세요.

학습 4회는 2026-11-05, 보관 모델의 4·5월 평가 8건은 2026-11-08에 완료했습니다. 아래 작성 당시 점검과 실제 GPU 결과를 구분합니다.

합성 데이터 CPU 테스트는 실제 성능 결과가 아닙니다. 모델 크기·마스킹·역전파,
실제 짧은 학습과 정확한 재개, 4조건 실행과 완료 결과 재사용, 설정/손상/표본 불일치 검출을
검사합니다. 실제 HDF5 데이터 재생성 및 Colab GPU 본학습은 작성 시 실행하지 않았습니다.

작성 시 검증: macOS arm64 / Python 3.12.14 / Torch 2.15.0 / NumPy 2.3.5에서
6개 테스트 통과. 이 환경은 기존 GPU 실험 환경과 다르며 검증 점수 비교에 사용하지 않았습니다.

## 보관 모델의 4·5월 최종 평가

[평가 전용 Colab 노트북](M3_width_final_evaluation.ipynb)은 검증된 학습 ZIP 복원 → 데이터 준비 → 동작 검사 → 8회 평가 → Drive 보관을 실행합니다. 원본 학습 ZIP은 담당자에게 받아야 하며 저장소에 포함되지 않습니다.


`final_evaluate.py`는 `runs/`에 보관된 서비스당 200/1,000개 × seed 201/202의
`best.pt` 4개만 평가합니다. 학습이나 모델 선택을 다시 하지 않습니다.
4월을 주 평가, 5월을 시간 변화 평가로 삼고, 기존 평가 코드의 전체 표본·학습 입력
중복·비중복·공통 미관측 그룹을 그대로 사용합니다. 비교 대상은 기존 M3의 같은
seed·예산 결과이며 기존 보고서의 seed 5개 평균과 섞지 않습니다.

새 런타임에서는 먼저 원본 결과 ZIP의 SHA-256을 확인하고 `runs/` 전체와 `run.py`를
복원한 다음, 위 데이터 준비 단계로 원본 NPZ를 재생성·검증합니다. 학습 셀은 실행할
필요가 없습니다. 최종 평가 파일을 이 폴더에 둔 뒤 GPU에서 실행합니다.

```sh
python experiments/2026-11-05_m3_width/final_evaluate.py --self-test
python experiments/2026-11-05_m3_width/final_evaluate.py
```

평가 전에 네 모델의 2월 예측을 재실행해 저장된 확률과 예측 라벨을 대조하고,
체크포인트·코드 해시와 환경을 `final_evaluation/run_context.json`에 고정합니다.
각 평가의 `predictions.npz`로 저장된 지표를 재계산하며, 기존 M3의 평가 입력·라벨·
순서 해시와 그룹별 표본 수·클래스별 개수도 대조합니다. 완료된 평가는 재사용합니다.
설정·환경이 달라지면 같은 출력 폴더를 이어 쓰지 않습니다.

`final_evaluation/summary.json`에 총 8회 평가와 대응 비교·seed 평균이 저장됩니다.
Colab의 후속 평가 셀은 코드·지표·예측을 별도 ZIP으로 묶고 기존
`내 드라이브/QUIC_M3_results/`에 저장한 뒤 사본 SHA-256·ZIP CRC를 확인합니다.
체크포인트는 원래 학습 ZIP에 그대로 보관합니다.

두 seed의 결과이며, 기존 A100과 새 Colab 환경의 차이를 함께 기록합니다.
평가 결과를 보고 추가 조정한다면 4·5월 데이터는 재사용된 테스트가 되므로,
그 이후의 최종 일반화 검증에는 별도의 미관측 데이터가 필요합니다.

2026-11-08 실제 실행: T4 / Torch 2.14.1+cu130에서 합성 추론·저장 지표 재계산·
완료 결과 재사용·잘못된 ID/중복 그룹·예측 파일 손상 검사를 통과했습니다.
기존 NPZ 해시와 네 모델의 2월 예측 라벨 재현을 확인한 뒤 8/8 평가를 완료했습니다.
모든 대응 조건에서 정답률과 Macro-F1이 개선됐습니다. 아래는 전체 평가 표본의 두 seed 평균입니다.
