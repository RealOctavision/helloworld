## 적용한 설계

승인 기록은 [restart_decisions.md §8](../2026-10-28_data_audit/restart_decisions.md)이고, 실제 설정은 [config.json](config.json)이다. 아래 구현 기본값은 검증으로 최적화한 값이 아니다.

- 대표 과제: Google 포함 혼합20. 최대30 PPI `[IPT_ms, DIR, SIZE_bytes]`, 짧은 플로우 포함.
- 교사: 공개 30pktTCNET의 pooling 직후448 → 새 분류기. 20클래스 **695,593개**. M1 BN 통계 갱신, M2 통계 유지·나머지 전체 미세조정, GeM p 학습 가능.
- 학생: Conv1D 3→32→64→64, 모두 커널3, 패킷 마스크·평균 집계. 20클래스 **20,180개**. M3/M4/M5 동일 구조·초기값·shuffle 규칙.
- AdamW, 배치128. LR 후보 M1 `1e-4/3e-4/1e-3`, M2 `1e-5/3e-5/1e-4`, 학생 `3e-4/1e-3/3e-3`. 학생 LR은 M3에서 선택해 공통 적용.
- 50 epoch는 개발 출발 후보이며 `epochs_frozen=false`. 본 실험 전에 공통 길이와 선택 설정을 고정해야 한다. 특정 본 실험 모델만 연장하지 않는다.
- KD α=`0.1/0.25/0.5`, T=`1/2/4`, 개발용2회. M4/M5의 학생 검증 Macro-F1 네 값을 평균해 공통 α·T를 선택한다. 본 실험5회.
- 구현 기본값: 개발 seed101/102, 본 실험201~205, 검증 추출 seed20261030. 고정 변환 `SIZE/1500`, `log1p(IPT_ms)/log1p(65000)`, DIR 유지. 공식 범위로 clipping 후 패딩0 유지. 시간창 crop 없음.
- 구현 기본값: AdamW weight decay `1e-4`, warm-up5 epoch 뒤 cosine 감소, 추가 증강/L2SP/LDIFS/계층별 LR 미적용. M0 learning rate0.05, 최대500 round, patience30, min_child_samples20, lambda L2=1, leaves7/15/31. 개발 탐색 전에 그대로 기록된 값이며 필요 시 개발 단계에서 변경 이력을 남겨야 한다.
- 최종 모델 선택은 **2월 검증 Macro-F1 → 동점이면 낮은 GT CE → 이른 epoch**. last checkpoint는 복구용으로 별도 보관한다.

## 실제 데이터 준비 결과

원본 HDF5 SHA256은 기존 감사와 일치했다. 읽기 전용 감사 cache의 PPI·라벨·ID를 원본 HDF5의 4개월 48개 기록과 대조했다. 해당 검사도 통과했다.

| 구성 | 1월 입력 행 | 정제 후 고유 입력 | 서비스당 최소 | 2월 검증 |
|---|---:|---:|---:|---:|
| 혼합20 | 567,806 | 560,745 | 1,173 | 4,000 |
| Google 미포함13 | 233,433 | 222,826 | 1,858 | 2,600 |
| Google 계열20 | 456,690 | 450,027 | 1,034 | 3,933 |

Google 계열20의 Hangouts는 2월 가용 기록133개를 사용했다. 나머지 서비스는 최대200개다. 1월 정제는 **해당 구성의 1월 입력·라벨만**으로 처리했다. 같은 입력·같은 라벨은 최소 원본 ID 1개를 대표로 남기고, 같은 입력·다른 라벨 그룹은 전부 격리했다. 라벨 기반 정제에서 접근한 정답 수를 manifest에 별도로 기록했다.

학습 후보 전체를 저장한 숫자와 모델이 실제 fitting하는 라벨 수는 다르다. 각 seed의 학습 파일에 클래스별 순위 `rank`를 저장했으며 `rank < 50/100/200/1000`으로 중첩 표본을 선택한다. 개발용 파일은 200개까지, 본 실험용은 1,000개까지 보존했다. 모델 간 동일 파일을 사용한다.

| 구성 | 4월 전체 평가 | 5월 전체 평가 |
|---|---:|---:|
| 혼합20 | 379,194 | 365,258 |
| Google 미포함13 | 252,471 | 225,067 |
| Google 계열20 | 237,389 | 233,986 |

4·5월은 데이터 목록과 겹침 마스크만 생성했고 **모델 점수는 계산하지 않았다**. 자연 입력 반복·라벨 충돌은 평가에서 삭제하지 않았다. 전체/해당 seed·예산의 실제 학습 입력 겹침/비겹침, 공통 미관측을 분리할 수 있다. 공통 미관측 제외 키는 사전 확정된 본 실험5개 seed의 최대1,000개, 개발2개 seed의200개, 공통 검증의 합집합이다. 학습에 선택하지 않은 1월 전체 풀을 제외 키로 사용하지 않는다.

동일 원본 ID의 분할 간 재등장은 없다. 이것이 모든 동일 세션의 분리를 증명하거나 공개 사전학습 원천과의 중복 부재를 보장하는 것은 아니다. 4·5월은 이전 연구에서 확인한 자료이므로 완전 미사용 최종 테스트라고 부르지 않는다.

`prepared/manifest.json`은 파일 SHA256과 클래스 순서를 포함한다. 각 구성의 `january_curation.npz`에는 대표 ID·그룹 크기·충돌 여부·보존 여부가 남아 있다. 전체 준비 산출물은 약128.6MB다.

## 짧은 실행에서 확인한 것

[smoke_v2/summary.json — 원본 로컬 보관](../../PUBLICATION.md#omitted-artifacts)이 성공한 실행이다. 혼합20·개발 seed101의 클래스당50개(총1,000개), 공통 검증에서 클래스당10개(총200개)를 사용했다. 신경망은 **2 epoch**, M0는 최대20 round만 실행했다. α0.25/T2는 연결 점검용 한 조합이며 선택 완료된 증류 설정이 아니다.

- M0~M5 모두 실제 입력→학습→저장→검증 예측이 통과했다.
- 신경망 손실·기울기·예측이 유한했다. 손실에 따라 실제 업데이트가 수행됐다.
- M3/M4/M5 초기 state SHA256과 M0~M5 학습 ID SHA256이 각각 동일했다.
- M1 BN 통계는 갱신됐고 M2의 사전학습 BN 통계는 유지됐다.
- M1의 dropout을 포함한 다음 업데이트를, 중단하지 않은 경우와 checkpoint에서 복구한 경우에 비교했다. **다음 손실과 전체 state가 정확히 일치**했다. optimizer/scheduler/RNG도 복구했다.
- M0의 저장·재로드 예측이 정확히 일치했다. 틀린 교사 라벨 예산·출력 클래스 순서·학습 ID를 거부하는 경로도 확인했다.
- 13/20클래스 출력 크기, α0과 직접 CE의 gradient 일치, DIR 제거 시 마스크 보존, 빈 부분집합 N/A를 확인했다.
- 데이터의 중첩·균등·고유 입력 조건을 확인했다. 구성별 4/5월 각각256개 기록에 대해 Python byte-set 방식으로 실제 겹침 마스크를 독립 계산해 대조했다. 이는 별도 에이전트 검증이 아닌 동일 작성자의 다른 계산 방식이다.

총 점검 실행은 약 **72.8초**, 해당 프로세스의 최고 RSS는 약 **1.12GB**였다. 이는 모든 점검을 포함한 프로세스 수치이며 모델별 독립 메모리나 T4 VRAM 수치가 아니다. 개별2-epoch 점수는 본 성능 결과로 해석하지 않는다.

### 확인 과정의 수정 이력

- 기존 Python 환경에 LightGBM4.6.0을 추가했다. macOS OpenMP 경로는 `run.sh`에서 이미 설치된 Torch의 라이브러리를 사용한다. 시스템 라이브러리를 설치·변경하지 않았다.
- 첫 smoke는 공식 패키지의 보조 `histc(Int)` 호출이 CPU Torch에서 지원되지 않아 멈췄다. 패킷 크기 빈도 카운터만 비활성화했다. 이 카운터는 이번 분류 입력·출력이나 손실에 사용되지 않으며, 미관측 임베딩 교체 기능도 사용하지 않는다. 모델 구조·학습 파라미터·GeM을 바꾸지 않았다. 최초 실패 기록은 `smoke/summary.json`에 보존했다.
- 검증셋 자체는 Common-unseen이 될 수 없으므로 smoke 보고의 해당 부분집합을 빈 집합으로 바로잡았다. 모델 가중치·예측·선택은 변경하지 않았다. 변경 전 보고서 해시는 `verification.json`에 보존했고, 현재 검증 코드는 오류를 자동 수정하지 않고 실패시킨다.

## 시간 산정과 현재 한계

로컬 CPU 학습2스레드와 실제 4,000개 검증 forward를 측정해, 50 epoch 가정으로 선형 추정했다. [timing_estimate.json](timing_estimate.json)에 근거가 있다.

| 범위 | 로컬 CPU 신경망 시간의 대략적 추정 |
|---|---:|
| 혼합20·200개 본 실험5회, M1~M5 | 약6.0시간 |
| 개발 LR 및 KD 탐색, 개발2회 | 약7.5시간 |
| 혼합20·50/100/200/1,000개 본 실험5회 | 약32.0시간 |

이 수치는 짧은 실행의 선형 계획값이며 장시간 발열, 최종4/5월 평가, LightGBM, 환경 준비·전송은 제외했다. 개발 과정에서 epoch 상한이 바뀌면 달라진다. 학생은 빠르지만 큰 교사의 학습·매 epoch 검증이 비용 대부분을 차지했다.

**T4는 측정하지 않았다.** 이후 사용자 요청으로 A100을 사용했고 실제 GPU 속도 측정 후 개발 실행을 시작했다. 상세 환경·예상 시간·상한은 아래 A100 절을 따른다. CPU와 GPU 추정치를 혼동하지 않는다.

2-epoch 학생의 CPU batch1 forward 중앙값은 약0.043ms, 교사는 약0.38ms였다. 초기 단일 실행의 처리시간 점검 수치이며 정식 학습 모델의 반복 벤치마크 결과는 아니다. 실제 트래픽 관측 대기시간도 포함하지 않는다.

## 실행 방법

프로젝트 루트에서 기존 환경을 사용하는 명령이다. 기존 준비 데이터와 성공한 smoke 결과를 덮어쓰지 않는다.

```sh
sh experiments/2026-10-30_midterm_restart/run.sh data.py self-test
sh experiments/2026-10-30_midterm_restart/run.sh data.py prepare
sh experiments/2026-10-30_midterm_restart/run.sh verify.py
```

새로운 짧은 점검이 필요한 변경이 있을 때만 별도 이름으로 실행한다.

```sh
sh experiments/2026-10-30_midterm_restart/run.sh smoke.py --output smoke_new
```

`data.py prepare`는 완성된 manifest가 있으면 파일 해시와 설정을 확인하고 재생성하지 않는다. `read_split`도 읽는 파일의 해시를 검사한다. `training.py`는 fitting·KD 교사 일치·checkpoint 재개·평가의 공통 구현이다. 본 실험 `phase=main`은 학습 길이가 확정되지 않은 현재 설정에서 거부한다. 개발 실행기는 Colab에서 시작했고 자동작업 `a100`은 점검·회수·해제만 담당한다. 추가 탐색이나 본 실험을 자동 시작하지 않는다.
